# 검색 수단과 위임의 선택

검색은 직접 수행하는 것이 기본이다. 이번 질문에 필요한 대규모 지식이 여러 저장소·모듈·문서에 흩어져 있어 넓은 탐색과 압축이 필요할 때만 위임한다. 시스템 전체가 크거나 MAGMA/Semble을 사용한다는 이유만으로 위임하지 않는다. 검색 수단은 질문이 요구하는 코드의 위치·세대에 맞춰 별도로 고른다.

| 질문의 대상 | 검색 수단 | 인계와 확인 경계 |
|---|---|---|
| 위치를 아는 파일·정확한 문자열의 작은 조회 | 해당 파일 직접 읽기 또는 제한된 rg | 불필요한 색인·작업자 호출 없이 현재 원문 확인 |
| 로컬 체크아웃에서 구현 위치를 모르는 의미 기반 코드·문서 탐색 | 가용한 Semble MCP, 없으면 기존 Semble CLI | 저장소 루트와 실제 반환 경로·범위 보존; 현재 로컬 상태와 원격 최신 상태 구분 |
| MAGMA 레거시 화면·서비스·SP 동작 | MAGMA search_magma → 필요한 read_source | 생성 설명은 후보이며 source_ref는 같은 공급자에 그대로 전달 |
| 정확한 테이블·SP·Form의 관계 또는 로컬 관계 그래프 | 해당 환경의 MAGMA KG 또는 Graphify 등 관계 도구 | 그래프는 탐색 근거이며 실제 호출·실행은 필요한 원문에서 확인 |
| 로컬 구현과 레거시 동작의 비교 | 질문을 두 대상으로 나누어 필요한 공급자만 사용 | 저장소·스냅숏을 섞지 않고 실제 연결이 미확인이면 표시 |

## Semble을 사용할 때

- 프로젝트 지침 또는 사용자가 지정한 저장소 루트를 사용한다. 홈·상위 폴더 전체로 자동 확대하거나 원격 저장소를 새로 복제하지 않는다. WorxSales 개인 설치의 실제 경로는 전역/프로젝트 지침에서 읽으며 플러그인에 개인 절대경로를 고정하지 않는다.
- 코드 위치만 필요하면 code, 문서면 docs, 설정이면 config, 여러 종류의 근거가 필요한 질문이면 all을 선택한다. 현재 MCP 스키마나 CLI 도움말이 지원하는 인자만 사용한다. CLI 옵션을 MCP 필드라고 가정하지 않는다.
- 반환된 코드 조각이 주장에 필요한 조건을 충분히 포함하고 파일·범위가 확인되면 그 부분을 불필요하게 다시 읽지 않는다. 조각이 잘렸거나 호출 경로·현재 편집 상태·예외가 판단에 필요하면 해당 로컬 원문만 보완한다. 관련성 점수는 정확도 보증이 아니다.
- 여러 저장소 결과의 접두 경로는 반환된 저장소 매핑으로 해석한다. 파일 이름만으로 저장소를 추정하지 않는다. Git HEAD만으로 미커밋 변경 상태까지 고정됐다고 보지 않는다.
- 색인은 로컬 검색 보조이며 원격 Git의 새 커밋을 자동 수신했다는 근거가 아니다. 제외·크기 제한·미지원 파일·검색 미발견을 기능 부재로 해석하지 않는다. 인덱스 재생성·Git pull·설치·설정 변경은 이 스킬만으로 승인되지 않는다.

## 병렬 탐색과 통합

작은 결과로 판단할 수 있으면 주 모델이 직접 검색하고 읽는다. 대규모 지식의 넓은 탐색·압축이 필요하다고 판단한 경우에만 작업자에게 대상 루트와 맥락을 전달한다. 그 안에서 독립 범위가 있을 때 작업자를 나눌 수 있지만, 질문이 여러 개라는 이유만으로 병렬화를 강제하지 않는다. 부모가 먼저 전체 결과를 읽은 뒤 다시 위임할 필요는 없다.

예를 들어 거대한 MAGMA 시스템에서도 특정 조회 조건 하나를 확인하는 질문은 직접 처리한다. 반대로 로컬에서도 여러 저장소·모듈에 흩어진 구현 후보를 넓게 찾아 비교·압축해야 하면 위임한다. 넓은 탐색 이후 변경을 좌우하는 조건이나 근거 충돌은 주 모델이 해당 원문을 직접 확인한다.

이미 확보한 결과를 분할할 때에는 같은 결과 집합의 고유 파일/후보를 기준으로 배정한다. 페이지·cursor 기능이 실제로 없으면 인자를 만들지 말고 후보 목록을 나눈다. 서로 다른 검색에서 순위 1~2와 3~4를 골랐다는 이유만으로 중복 없는 분할이라고 보지 않는다.

Semble 자체에 전용 검색 에이전트가 이미 연결돼 있으면 같은 계약으로 재사용할 수 있다. 동일 후보에 전용 에이전트와 별도 Luna를 중복 파견하지 않는다. 두 공급자 결과를 합칠 때도 파일·세대가 같은지 확인한 뒤에만 중복으로 처리한다.

## 근거

[Semble 공식 안내](https://github.com/MinishLab/semble)의 CLI/MCP·다중 저장소·코드 조각·로컬 캐시 설명을 참고한다. 실제 설치 버전과 도구 스키마가 우선하며, 문서의 속도·토큰 절감 수치를 현재 작업의 보장값으로 사용하지 않는다.
