# 사용자가 마련해야 하는 외부 조건

아래 조건은 AI가 대신 만들 수 없거나, 사용자의 계정·비밀번호·결재가 필요합니다. 없으면 해당 행은 「실행 불가」로 남습니다. 준비 단계와 매 회차 보고에서 **조건마다 풀리는 행 수**를 세어 많은 순서로 사용자에게 알립니다. 사용자의 본인 계정만 건드리는 사전조건은 조율자가 직접 만들 수 있습니다([직접 만드는 사전조건](../../worxsales-qa-all-in-one/references/preconditions.md)).

| 조건 | 풀리는 행 | 확인 방법 | 사용자가 할 일 |
|---|---|---|---|
| Google Workspace 연결 | 메일 발송, 견적 메일, 캘린더 일정 조회·등록 | 앱의 Google 연결 화면 표시, 또는 앱 bridge `worxDesktop.gws.getConnection()`이 `ACTIVE`이고 `calendarRead`·`calendarWrite`·`gmailSend`가 true. `listCalendarEvents`로 일정 몇 건이 오는지 확인 | 앱의 Google 연결 버튼을 눌러 기본 브라우저의 OAuth 동의 화면을 마칩니다. 처음 보는 동의 화면이므로 AI가 대신 동의하지 않습니다 |
| MatrixCloud(MC) 로그인 | 「☎ 걸기」, 통화 도크의 통화 단계, MC 수신 | 별도 네이티브 앱입니다. 앱은 `ws://localhost:1040`에 붙습니다. `check_env.sh`의 matrix 줄: 101 = 정상, 503 = MC가 떠 있지만 로그인 전·준비 전, 연결 거부 = MC 미실행 | MC 앱을 켜고 직접 로그인합니다. AI는 비밀번호를 입력하지 않습니다(bws에 키가 있어도 사용자가 입력합니다) |
| MAGMA에서만 오는 데이터(예: 리드) | 리드 목록·상세·판정 | 리드 목록이 오류 없이 「0건」이면 데이터가 없는 것입니다. 503 `*_NOT_CONFIGURED`는 서버 설정 누락이라 데이터와 별개입니다 | MAGMA DEV 쓰기 권한자(DBA)에게 시드 데이터를 요청합니다. 요청서 틀은 [리드 시드 요청](lead-seed-request.md)입니다. Worxhub 같은 조회 도구로는 넣을 수 없습니다 |
| 두 번째 실제 사용자 계정 | 동시 편집, 다른 사람에게 보이는 알림·배정처럼 진짜 다중 사용자가 필요한 행 | 같은 계정을 슬롯 두 개에 띄워도 사용자는 한 명입니다 | 다른 사람의 계정을 빌려 로그인해 줄 수 있는지 묻습니다. 다른 담당자의 **기존** 레코드를 본인 계정으로 보는 것만으로 대부분의 「다른 담당」 행은 실행할 수 있으므로, 남는 행만 이 조건으로 셉니다 |
| 사용자의 브라우저 CDP | Google 캘린더 일정 만들기, OAuth 확인, 웹 화면 확인 | `curl -s 127.0.0.1:<port>/json/version` (예: Comet 9222) | 브라우저를 원격 디버깅 포트와 함께 켜 둡니다 |
| 역할 부여 권한 | 팀장·영업운영·조회만 역할 행 | 권한 관리 화면이 열리고 본인 사번 [확인]이 본인 이름을 보이는지 | QA 계정이 권한 관리자여야 합니다. 아니면 권한 관리자에게 부여를 요청합니다 |

## 브라우저를 CDP로 다룰 때

- 탭이 많은 브라우저에서는 Playwright `connectOverCDP`가 멈출 수 있습니다. raw CDP를 씁니다: `/json/list`로 탭을 고르고, 탭의 `webSocketDebuggerUrl`에 붙어 `Runtime.evaluate`를 보냅니다. 새 작업이 필요하면 `/json/new?<url>`로 임시 탭을 열고 끝나면 `/json/close/<id>`로 닫습니다.
- 스크립트는 반드시 `process.exit(0)`으로 끝냅니다. 연결이 남으면 다음 명령이 멈춥니다.
- `worxsales-qa-all-in-one/scripts/cdp_tab.mjs`가 이 방식의 도구입니다.
- 사용자 브라우저의 로그인된 세션은 사용자 본인 계정에만 씁니다. 처음 보는 동의 화면, 비밀번호 입력, MFA는 사용자에게 넘깁니다.
