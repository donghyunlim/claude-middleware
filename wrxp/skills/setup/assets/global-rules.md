## wrxp

Use available wrxp skills only when their scope matches the task. Keep detailed procedures in the plugin, not in this file. Preserve user/project instructions and existing approvals; simplify small edits and do not stack full pipelines for the same phase.

- Development: use `wrxp:staged-development` for medium/large work or unresolved major decisions. If unavailable, reuse one canonical plan and proceed through outline agreement → core implementation/review → detail/tests; consult the user when scope or important decisions change.
- Tests: use `wrxp:test-runner` for already-needed checks. Otherwise run existing project commands and retain command, exit status, and raw evidence. Do not repeat or expand checks without relevant changes, failures, or concrete risks.
- Search: search directly by default. Use `wrxp:search-delegation` only for broad discovery/compression across substantial scattered knowledge. Otherwise, if delegation is needed and the skill is unavailable, pass context, question, scope, and stopping conditions; require source locations and check decisive conditions/conflicts. System size, MCP availability, or several queries alone do not justify delegation.
- Coding: use `wrxp:code-delegation` for approved independent implementation. Otherwise hand off the existing plan, ownership, and acceptance criteria; the worker implements and self-tests without recursive delegation. Pin `gpt-6-sol` with `medium` by default or AI-selected `high` for complex work; exclude low, omitted effort, and silent model fallback. Claude must use a Codex execution path that pins both values, not an OpenAI ID in `Agent.model`. Keep tiny edits direct. Accept adequate current-code evidence without automatic whole-task re-review; investigate concrete risks and honor requested reviews.
- Session transfer: use `wrxp:handoff` only when explicitly invoked by the user. Do not start it during routine summaries or completion.
- Orchestration: `wrxp:ha`, `wrxp:haq`, `wrxp:haqq`, `wrxp:haqqq` handle a convergent task; `wrxp:cast`, `wrxp:castq`, `wrxp:castqq`, `wrxp:castqqq` handle useful parallel perspectives. Choose only when requested or relevant; question depth does not select the model. Use `wrxp:breakdown` for decomposition/execution, `wrxp:decompose` for decomposition only, and `wrxp:agent-match` for agent/DAG matching. Keep the current development stage and permission boundaries.
- Setup: use `wrxp:setup` only for requested setup/update/removal of these connections, not on every task. Never treat setup or delegation as permission to install unrelated tools, access credentials, commit, push, or deploy.
