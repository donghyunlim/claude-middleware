# 본인 한정 조작

사용자가 그 실행의 쓰기 범위로 「본인에게만 보내는 발송·통화」나 「결과가 본인 계정에만 미치는 쓰기」를 허용했을 때 지키는 규칙입니다. 쓰기 범위 파일의 형식과 허용 절차의 정본은 [쓰기 범위](../../worxsales-qa-all-in-one/references/write-scope.md)입니다. 본인 주소·번호(`self`)는 작업 폴더의 `refresh/write_scope.json`과 레인 WORKER.md에 있고, 이 스킬에는 적지 않습니다.

## 발송·통화

1. 받는 사람 칸 전부(받는 사람, 참조, 숨은 참조, 문자 번호, 통화 번호)를 누르기 **직전에** `text`로 읽고 번호 박스 그림으로 남깁니다. 확인 창 없이 바로 보내지는 버튼이 많아, 누른 뒤의 확인으로는 늦습니다.
2. 모든 받는 사람이 `self`의 값일 때만 누릅니다. 하나라도 다른 값이 있고 지우거나 바꿀 수 없으면 누르지 않고 「실행 불가」(받는 사람을 본인으로 바꿀 수 없음)입니다.
3. `details.self_recipient`에 화면에서 읽은 받는 사람 목록을 적습니다(마스킹된 값이면 마스킹된 그대로).
4. 다른 사람이 작성한 견적·기록에서는 서버에 저장하는 다음 단계(예: 「다음: 작성 및 발송」)로 넘어가지 않습니다. 발송 행은 본인이 만든 `QA-` 견적으로 합니다.

## 본인 계정에만 닿는 쓰기

1. 실행 **전**에 영향 대상(레코드, 회원의 서비스별 담당, 작성자, 받는 사람, 공유 범위)을 화면에서 읽습니다.
2. 실행 **후**에 다시 읽어 다른 사용자·고객 데이터가 바뀌지 않았는지 확인합니다.
3. `details.self_only_check`에 `{"before": "…", "after": "…"}`로 남깁니다.
4. 팀 전체 배포, 공용 데이터 교체, 고객 발송·통화, 다른 사람 레코드·권한처럼 다른 사람에게 닿을 수 있으면 하지 않고 「실행 불가」(이번 실행의 쓰기 범위 밖)입니다.

## 만들 수 없는 상황

- 받을 수 없는 주소(예: `qa-fail@example.test`)도 Gmail은 보낼 때 받아들여 「발송 성공」이 됩니다. 발송 시점의 실패를 요구하는 기대결과는 이 방법으로 확인할 수 없으므로, 확인한 부분과 나눠 「부분 OK」 또는 「실행 불가」로 적습니다.
