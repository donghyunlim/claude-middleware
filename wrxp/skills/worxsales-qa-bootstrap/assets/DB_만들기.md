# 테스트 시나리오 DB 만들기 (재현 방법)
> 이 페이지는 「WorxSales 테스트 시나리오」 DB를 어떤 원천에서 어떤 절차로 만들었는지 기록합니다. 같은 절차를 다시 실행하면 같은 TC ID 기준으로 행이 갱신됩니다.

## 1. 원천과 우선순위
| 순위 | 원천 | 쓰는 내용 |
|---|---|---|
| 1 | 역할·권한 정리 문서 | 역할 판정, 메뉴별 조회 범위, 동작별 허용 조건, 「조회만」일 때 막을 동작, 정책과 다른 개발 현황 |
| 1-1 | 화면 인벤토리의 CBT 제공 범위 | 지금 CBT에서 실제로 제공하는 범위. 미제공·제거 화면과 기능은 미노출 확인만 둠 |
| 2 | 기능정의서의 메뉴별 화면 정의 | 필드·필수값·검증 규칙·오류 코드·상태·수용 기준(AC) |
| 3 | 목업 (버전: 이 표에 적음) | 참고만 함. 기능정의서와 다르면 기능정의서를 따름 |
- 화면 정의에 "확정 필요"로 적힌 규칙은 `정책 상태`를 「확정 필요(보류)」로 둡니다.
- 정책과 다르게 개발된 곳으로 문서에 적힌 동작은 `구현 상태`를 「정책과 다름」으로 둡니다.

## 2. 행 단위와 컬럼
- 한 행은 **시나리오 × 역할 × 대상 관계**입니다. 기대결과가 달라질 때만 역할별로 행을 나눕니다.
- 작성 규칙 전문은 작업 폴더의 `scenarios/GUIDE.md`에 있습니다.

## 3. 작업 폴더와 스크립트
- 스크립트는 wrxp 플러그인의 `worxsales-qa-bootstrap`, `worxsales-qa-refresh` 스킬에 들어 있습니다.
- Notion 키는 Bitwarden Secrets Manager의 `NOTION_API_KEY`를 `bws-run`으로 주입하고, 작업 폴더의 `scripts/run.sh`·`refresh/run.sh` 래퍼를 거쳐 실행합니다.
