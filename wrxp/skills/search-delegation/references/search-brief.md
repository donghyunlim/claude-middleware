# 맥락을 담은 검색 의뢰

## 작성 기준

대규모 지식을 넓게 탐색·압축해야 하여 위임을 선택한 경우에만 이 의뢰를 작성한다. 좁은 조회에는 직접 검색하며 의뢰 양식을 만들지 않는다. 아래 항목은 현재 대화와 정본에서 필요한 맥락을 짧게 정리하기 위한 체크리스트이며, 별도 기획서나 계획 모델 호출을 요구하지 않는다.

| 항목 | 전달할 내용 |
|---|---|
| 현재 작업 | 만들거나 조사하는 대상과 현재 단계 |
| 사용자 상황·목적 | 왜 필요한지, 누가 어떤 결과를 사용할지 |
| 이번 결정 | 검색 결과로 판단할 구체적인 질문 |
| 확정 사항·제약 | 합의된 정책, 바꿀 수 없는 조건, 제외 범위 |
| 기존 지식·공백 | 확인된 사실과 근거 위치, 아직 모르는 것 |
| 담당 범위 | 검색 축 또는 후보 ID, 선택한 검색 수단·저장소 루트·스냅숏, 실제 도구 접근, 다른 작업자와의 경계 |
| 중요한 발견 | 반드시 보존할 조건·예외와 가설을 반박할 근거 |
| 종료 조건 | 충분한 결과의 기준, 시간·범위 상한이 있으면 그 한도, 미확인으로 남길 수 있는 부분 |

정본을 참조할 때에는 정확한 경로·버전과 필요한 절을 지정한다. 작업자가 접근할 수 없으면 관련 부분만 발췌한다. 이름·직책 등 개인 정보가 판단에 불필요하면 역할과 제약으로 표현한다.

## 예시: 일반 이관과 휴가 이관의 공통화 검토

**부족한 의뢰:** “담당자 이관 코드를 찾아서 요약해 줘.”

**작업 맥락을 전달한 의뢰:**

> 현재 새 CRM의 담당자 일괄 이관 기능을 기획하고 있다. 구현은 아직 하지 않는다. 일반 이관과 장기휴가 이관이 같은 저장 규칙을 공유하는지 판단할 근거가 필요하다. 기존 권한·대상 제외 규칙은 보존하지만 화면 배치를 그대로 복제할 필요는 없다. 기존에 확보한 후보 목록 중 배정된 항목의 대상 선정·저장 호출·이력 처리를 조사하라. 공통화 가능한 부분뿐 아니라 공통화를 막는 조건과 반례를 남겨라. 검색 설명과 원문 확인 결과를 구분하고, 실제 호출 연결을 확인하지 못하면 추정으로 연결하지 말라. 차이와 근거가 충분하면 반환하고, 남은 공백은 영향을 받는 결정 및 다음 조회와 함께 적어라.

실제 파견에는 이 문구를 그대로 복사하기보다 현재 정본과 사용자 합의에서 내용·담당 후보를 채운다. 예시의 업무 규칙을 실제 시스템의 사실로 취급하지 않는다.

## 소비 가능한 인계

요약은 “현재 질문에 대한 답 → 중요한 발견과 조건 → 주장별 근거 → 판단에 영향을 주는 미확인 사항”으로 구성한다. 모든 파일의 상세 요약은 필요하지 않다. 원문 전체는 접근 가능한 별도 기록에 보존하고 인계에 자동 첨부하지 않는다.

근거 ID가 지원되면 반환된 ID로 연결한다. 그렇지 않으면 도구가 반환한 source_ref·경로·실제 행 범위를 그대로 사용하거나 보존된 도구 기록을 참조한다. 메타데이터를 기억으로 재작성하지 않는다. 원문을 읽지 않은 후보는 검색 설명 수준으로 표시한다.

후속 의뢰는 기존 의뢰의 식별자·유효한 근거와 새 질문·변경된 제약만 전달한다. 이전 인계에 없는 내용을 확인한 것으로 간주하지 않는다.
