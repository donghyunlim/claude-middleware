# Changelog

이 문서는 wrxp 플러그인의 사용자에게 영향을 주는 변경 사항을 기록합니다.

## [0.1.47] - 2026-10-09

- `worxsales-qa-executor` 판정 규칙을 보완했습니다. 화면 전체가 「준비 중」이면 그 안의 노출 확인 행도 「미구현」이고, 정책이 「확정 필요(보류)」인 행은 화면이 없어도 「보류-기록」입니다.
- 실행 규칙: 결과 파일은 행이 끝날 때 바로 쓰고, `app.mjs` 명령은 `timeout 60`으로 감쌉니다. 병렬 실행에서는 조율자가 Notion 게시를 모아서 할 수 있습니다.

## [0.1.46] - 2026-10-09

- `worxsales-qa-executor` 병렬 실행 규칙에 `pkill`·`killall` 금지를 추가했습니다. 한 실행자가 이름으로 프로세스를 끄면 다른 실행자의 앱 조작 명령까지 끊깁니다.

## [0.1.45] - 2026-10-09

- `worxsales-qa-executor`에 「부분 OK」 판정을 추가했습니다. 확인한 기대결과는 맞지만 필수 기대결과 일부를 환경·도구 문제로 확인하지 못한 행은 「OK」가 아니라 「부분 OK」로 두고, 남은 검증을 `details.unverified`에 남깁니다.
- `publish_results.py`가 재검증 기록(`final_verdict`만 있는 파일)을 「이전 실행 기록」에 넣으려다 멈추던 문제를 고쳤습니다.

## [0.1.44] - 2026-10-09

- `worxsales-qa-executor`에 전체 스캔(2,400여 행, 병렬 실행자 5명)에서 정한 실행 규칙을 넣었습니다.
- 역할: 비영업자 역할은 첫 행 전에 역할 확인 게이트를 거칩니다. 역할 전용 기능이 없거나 「조회만」 차단 안내가 빠진 동작은 「문제」가 아니라 「미구현」(outcome 「권한 미적용: 」)으로 판정합니다. 역할 부여는 이름을 확인한 본인에게만 합니다(`references/roles.md`).
- 판정: 요소가 아예 없으면 「미구현」, 있는 기능이 문서와 다르게 동작할 때만 「문제」입니다. 근거 조항을 인용하고 문서를 넓게 읽지 않습니다. 「문제」는 다른 실행자가 재검증한 뒤 확정합니다(`references/reverify.md`).
- 환경: 로그인 화면의 연결 환경(DEV/STG/PRD)을 확인하고, 로그인은 앱·브라우저 조작으로 직접 처리합니다. 파일 저장 버튼(PDF 다운로드)과 UI 시연 모드를 금지했습니다.
- 병렬 실행: 실행자마다 앱 하나, 자기 파일만 수정, 와일드카드 `rm` 금지, 배치 번호 재사용 금지, 실제 시각 기록, 같은 차단 화면의 그림 공유 규칙을 정했습니다.

## [0.1.43] - 2026-10-09

- Claude 위임 모델 배분을 바꿨습니다. `/ha`의 Claude 실행자는 Haiku 5.5가 기본이고, 여러 단계를 스스로 판단하는 긴 작업, 화면 판단, 원인이 불분명한 디버깅, 설계 판단이 필요한 여러 파일 수정, Haiku가 한 번 실패한 작업만 Sonnet 5.5로 올립니다.
- `fast-worker`의 Claude 폴백을 Sonnet 5.5에서 Haiku 5.5로 바꿨습니다.

## [0.1.42] - 2026-10-06

- `worxsales-qa-executor` 시험 실행에서 찾은 결함을 고쳤습니다.
- 증거 번호표: 숫자(①②③)는 재현 단계만 가리키고, 보조 표시는 행 전체에서 이어지는 알파벳(Ⓐ Ⓑ)을 씁니다. 번호표를 박스의 오른쪽 위 모서리에 붙여 요소와 이웃의 글자를 가리지 않게 했습니다.
- 결과 페이지: 재현 순서에 번호가 두 번 붙던 문제를 고쳤습니다. 본문의 「🤖 자동 실행 결과」 제목부터 아래만 다시 쓰고, 그 위에 사람이 남긴 메모는 보존합니다. 인식하지 못한 본문은 지우지 않습니다.
- 앱 조작: 이름은 정확히 일치하는 요소를 먼저 찾고, 없을 때만 부분 일치로 찾습니다. 값·비활성·선택·스크롤 위치와 일치 개수를 읽는 `probe` 명령을 추가했습니다.
- SKILL.md: 스크립트 경로를 스킬 폴더 기준으로 명시했고, 이미 로그인된 앱을 먼저 확인한 뒤 필요할 때만 다시 띄우도록 순서를 정리했습니다.

## [0.1.41] - 2026-10-06

- 명시적으로 호출하는 `worxsales-qa-executor` 스킬을 추가했습니다. WorxSales 테스트 시나리오 행을 로그인된 실제 Electron 앱에서 한 행씩 실행하고, 판정·번호 박스 증거·읽기 쉬운 결과를 Notion 시나리오 DB에 반영합니다.
- 행마다 locator나 Playwright 스크립트를 미리 만들지 않습니다. 에이전트가 화면에서 같은 개념의 요소를 찾고, 문서 이름과 앱 이름의 차이는 관찰로 기록합니다.
- 결과 페이지는 「결과 한눈에 → 증거(그림·번호) → 상세 기록(토글) → 이전 실행 기록」으로 나눕니다. 증거의 번호표와 재현 순서의 번호가 같은 장면을 가리킵니다.
- 쓰기 범위를 정하지 않으면 조회·차단 확인만 합니다. CDP 연결을 끊을 때 로그인된 앱을 닫지 않습니다. Claude Code의 `disable-model-invocation`과 Codex의 `allow_implicit_invocation: false`를 적용했고 다른 스킬·전역 셋업에 연결하지 않았습니다.

## [0.1.40] - 2026-09-30

- 사용하지 않는 `cast`, `castq`, `castqq`, `castqqq`(Team family)와 `test-runner` 스킬을 제거했습니다. 세션 기록상 cast 계열의 마지막 사용은 2026-06이었고, test-runner는 호출 기록이 없었습니다.
- `ha`·`staged-development`·`code-delegation`·전역 셋업 규칙·README에서 제거한 스킬에 대한 안내를 지웠습니다. 테스트는 기존 프로젝트 명령으로 실행하고 명령·종료 코드·근거를 남기는 규칙을 유지합니다.
- 모델 지정을 최신화했습니다. 코드 위임은 `gpt-6.1-sol`, `/ha` 역할표는 Claude Opus 5.5·Sonnet 5.5·Haiku 4.5, Codex utility는 `gpt-6-luna`입니다. Codex controller는 `gpt-6-astra`를 유지하고, standard executor는 `gpt-5.6-terra`에서 `gpt-6.1-sol`(medium, 가벼운 작업 low)로 바꿨습니다. verifier 기본값도 Sol입니다.
- Claude utility와 fast-worker는 Haiku 5.5 → Sonnet 5.5 low 순서를 따르며 Haiku 4.5는 쓰지 않습니다. Haiku 5.5가 아직 없으므로 fast-worker는 `claude-sonnet-5-5` + `effort: low`로 실행되고, 출시 후 모델 줄만 바꾸면 됩니다.

## [0.1.39] - 2026-09-30

- `intent-anchor` 스킬을 추가했습니다. 작업이 사용자의 원래 의도에서 벗어났는지, 세션 로그에서 추출한 사용자 발화 전부와 이전 핸드오프의 원문 인용을 기준으로 이 작업에 참여하지 않은 최고 수준 모델과 대조합니다.
- 두 계정이 모두 있으면 반대 계열(Claude 메인이면 Codex Astra, Codex 메인이면 Claude Opus), 한 계열만 있으면 그 계열 최고 모델을 새 맥락으로 씁니다. effort는 high, 권한은 읽기 전용이며 실제 모델·폴백 이력을 기록합니다.
- 명시 호출과 드문 자동 실행(방향 자체를 바로잡는 정정, 같은 목표의 반복 재시도)을 지원합니다. 드리프트가 확인되면 작업을 멈추고 질문 하나를 하며, 경로 수정은 사용자 답을 받은 뒤에만 합니다.
- `handoff`의 사용자 발화 추출기를 `shared/scripts/user_turns.py`로 옮겨 두 스킬이 공유합니다. 기존 `handoff` 경로와 동작은 유지됩니다.
- 추출기가 Codex의 목표 자동 문맥(`<codex_internal_context`)을 사용자 발화로 세던 문제를 고쳤습니다. `handoff`의 원문 인용에도 적용됩니다.

## [0.1.38] - 2026-09-28

- 명시적으로 호출하는 `cloudinfra-review` 스킬을 추가했습니다. 인프라 요청의 필수 정보, 신청 경로, 표준 구성, 담당 범위, 적용·검증 조건을 검토하고 제출 문안을 작성합니다.
- Jenkins 유지·GitLab CI 신규 구성·환경별 병존/이관을 구분합니다. CI 파일이나 SAST 성공을 배포 전환 완료로 오인하지 않고, 실제 적용 근거·중복 실행·기존 경로 종료 조건을 검토합니다.
- 작업 요청·검토 문의·장애 조사와 신청 경로 조정을 구분합니다. 확인되지 않은 사실·정책·승인·일정을 만들지 않고, 단순 표준 요청은 필요한 범위에서 짧게 처리합니다.
- Claude Code의 `disable-model-invocation`과 Codex의 `allow_implicit_invocation: false`를 적용했습니다. 기존 스킬·훅·전역 셋업 연결은 변경하지 않았으며 검토 호출만으로 외부 게시나 배포를 실행하지 않습니다.
- 실제 업무에서 도출한 검토 기준을 일반화했습니다. 공개 배포 파일에는 개인 이름·사내 주소·대화 원문을 포함하지 않고 가상의 예시를 사용합니다.

## [0.1.37] - 2026-09-27

- 관리 구역이 모호한 파일에는 원문을 보존하고 새 규칙만 추가하도록 셋업 방식을 변경했습니다. 갱신·제거는 안전하게 식별되는 구역에 한정하고 남은 기존 규칙을 알립니다.
- 공통 배포 규칙에서 다른 플러그인보다 wrxp를 우선한다는 선언을 제거했습니다. 사용자별 우선순위 선택은 개인 지침에만 유지하며 Sol 위임·자체 검증 방식은 유지합니다.
- `setup` 스킬로 Codex·Claude 전역 지침에 전체 wrxp 스킬의 짧은 연결 규칙을 설치·갱신·점검·제거할 수 있습니다. 스킬 본문은 플러그인에 유지합니다.
- 기존 사용자 설정과 OMC 구역을 보존하고, 읽기 전용 미리보기·변경 전 백업·중복 없는 재실행을 제공합니다. 개인 업무 경로·자격 증명·외부 도구는 복제하거나 자동 설치하지 않습니다.

## [0.1.36] - 2026-09-27

- `code-delegation` 스킬을 추가했습니다. 합의된 독립 구현은 GPT-6 Sol medium/high로 위임하고, 작업자가 구현과 자체 검증을 책임집니다. low·무단 모델 폴백·불필요한 메인의 전체 재검증을 제외합니다.
- 단계별 개발과 기존 라우팅에 코드 위임 우선 규칙을 연결했습니다. 검색·문서 모델 및 과거 실험 기록은 변경하지 않습니다. Sol의 속도·품질은 이번 정책 변경으로 검증된 것이 아닙니다.

## [0.1.35] - 2026-09-27

### Changed

- `handoff`의 최종 기획 상태에 "요청 범위(U번호)"를 추가했습니다. 사용자가 직접 요청한 작업을 그대로 수행한 항목이 "미승인"으로 표시되지 않고, 요청에 없던 방식·범위를 AI가 정한 항목만 미승인으로 표시합니다.
- 이전 핸드오프가 처음부터 없는 경우는 "없음", 재개한 흔적은 있으나 문서를 특정할 수 없는 경우는 "미확인"으로 구분합니다.

## [0.1.34] - 2026-09-27

### Fixed

- Claude Code 안에서 실행한 Codex처럼 두 런타임의 세션 ID가 함께 있는 환경에서 `handoff`의 원문 추출 스크립트가 Claude 세션을 읽던 문제를 고쳤습니다. 이제 `CLAUDE_CODE_SESSION_ID`와 `CODEX_THREAD_ID` 중 로그가 가장 최근에 기록된 세션을 사용합니다.
- `handoff` 스킬 설명에 Codex 호출 방식(`$wrxp:handoff`)을 명시했습니다. Codex는 `disable-model-invocation`을 적용하지 않으므로 사용자가 명시적으로 호출할 때만 사용하도록 설명문으로 제한합니다.

## [0.1.33] - 2026-09-27

### Added

- 사용자가 `/wrxp:handoff`로 호출할 때만 동작하는 `handoff` 스킬을 추가했습니다. 컨텍스트가 커진 세션의 작업을 새 세션이 이어받도록 사용자 의도 세트(최초 의도·작업 중 결정·최종 의도), AI 기획(핵심 포인트·최종 기획), 현재 상태, 문제점, 미결 사항을 한 문서에 기록합니다. 평가와 회고 없이 사실과 근거만 기록합니다.
- 압축 이후에도 최초 의도를 원문으로 인용할 수 있도록 Claude Code·Codex 세션 로그에서 사용자 입력만 추출하는 `scripts/user_turns.py`를 포함했습니다. 작업 중 보낸 메시지와 질문 도구(AskUserQuestion, request_user_input)의 답을 포함하고, 시스템 주입 문맥·작업 완료 알림·도구 결과·스킬과 자동화 주입을 제외합니다. 응답 없이 연속으로 재전송된 같은 메시지는 하나로 묶습니다.
- 재개 방법(첫 행동·다시 하지 말 것·상태 확인 명령), 세션 종속 자원과 외부 변경 목록, 새 서브에이전트가 문서만 읽고 고정 질문 5개에 답하는 콜드리드 검증을 포함했습니다.
- 핸드오프는 프로젝트 폴더의 `handoffs/`에 회차마다 새 파일로 저장하고, 이전 핸드오프의 최초 의도와 결정 목록을 승계합니다.

### Fixed

- 릴리스 버전 일치 테스트가 0.1.31을 기대하던 문제를 현재 버전에 맞췄습니다.

## [0.1.32] - 2026-09-21

### Changed

- 검색은 직접 수행하는 것을 기본으로 하고, 여러 저장소·모듈·문서에 흩어진 대규모 지식을 넓게 탐색·압축해야 할 때만 `search-delegation`을 사용하도록 범위를 좁혔습니다. 시스템 크기나 로컬/MAGMA 여부만으로 위임하지 않습니다.
- 의뢰는 현재 맥락·질문·범위·종료 조건을 짧게 정리하며, 별도 계획 모델 호출이나 검색 비율 할당을 요구하지 않습니다. 변경을 좌우하는 조건과 충돌 근거는 주 모델이 직접 확인합니다.
- 검색 범위 지시와 실제 접근 제한을 구분하고, 공급자 연결 실패를 해결하려고 과제 밖 세션·컴퓨터 상태를 탐색하지 않도록 명시했습니다. 새로운 권한 격리 기능이나 코드 위임 실행기는 포함하지 않습니다.
