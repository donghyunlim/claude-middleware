# Korean Polish

## 목적

완성된 한국어 산출물의 의미와 사실을 유지하면서 모호한 생략, 불완전한 종결, 명사 나열과 어색한 비유를 바로잡는 제출 직전 교정 절차입니다.

## 적용 범위

- 사용: 보고서, 공지, 메모, 제안서, 명세서와 한국어 결과물.
- 제외: 일반 대화, 초안 작성, 번역, 코드 리뷰와 의도적으로 지정된 문학적 문체.

## 교정 계약

원문의 주장, 사실, 수치, 확실성, 시제, 항목 순서와 형식을 유지합니다. `검토`, `예정`, `가능성`, `방향`, `판단`처럼 결정의 강도를 나타내는 표현도 보존합니다.

## 교정 절차

1. **보호 영역을 확정합니다.** 코드, 식별자, 명령어, 경로, API 필드, 로그, 오류, 커밋 메시지, 인용문과 영문 고유명사는 그대로 둡니다.
2. **의미 관계를 명확하게 합니다.** 문맥을 이해하는 데 필요한 주체, 대상, 조건과 영향 범위를 밝힙니다. 문맥으로 확정할 수 없는 정보는 추정하지 않습니다. 편집 메모를 허용한 경우에만 해결되지 않은 모호성을 `확인 필요`로 분리합니다.
3. **문장을 완결합니다.** 일반 문장은 서술어와 종결어미로 끝냅니다. 제목, 표, 레이블과 의도적인 짧은 목록 항목은 예외지만, 설명문으로 이루어진 목록 항목은 완결된 문장으로 교정합니다.
4. **어휘와 통사 구조를 다듬습니다.** 조사와 어미를 보완하고 명사 나열을 자연스러운 문장으로 바꿉니다. 불필요한 비유·과장·희귀어를 줄입니다.
5. **원문과 대조합니다.** 문장별로 사실, 수치, 부정 여부, 확실성, 시제, 기술 문자열, 순서와 형식이 달라지지 않았는지 확인합니다. 원문이 시제를 명시하지 않은 `[사건 명사구] + 가능성` 형태라면 사건 명사구를 그대로 유지하고 `가능성이 있습니다`라는 술어만 보완합니다. 예를 들어, `일부 요청 지연 가능성`은 `일부 요청의 지연 가능성이 있습니다`로 교정합니다. 이를 `일부 요청이 지연되었을 가능성`이나 `일부 요청이 지연될 가능성`으로 바꾸면 원문에 없던 시제가 추가되므로 허용하지 않습니다. 교정 과정에서 추가한 해석이 있다면 제거합니다.
6. **최종 결과를 반환합니다.** 사용자가 다른 출력 형식을 요구하지 않았다면 설명 없이 교정된 본문만 반환합니다.

## 빠른 참조

| 점검 대상 | 완료 조건 |
|---|---|
| 의미 | 필요한 주체·대상·조건이 분명하며 새 사실이 없습니다. |
| 문장 | 설명문이 명사구로 끝나지 않고 자연스럽게 종결됩니다. |
| 어휘 | 명사 나열과 불필요한 비유가 제거되었습니다. |
| 충실성 | 수치·시제·확실성·순서가 원문과 같습니다. |
| 보호 문자열 | 코드·경로·API 필드·오류·인용문이 그대로입니다. |

## 예시

교정 전: `API 교체가 완료됐음. 기존 설정 파일에도 경고가 추가됐음.`

교정 후: `API 교체가 완료되었습니다. 기존 설정 파일에도 경고가 추가되었습니다.`

## 흔한 실수

- 문장을 짧게 만든다는 이유로 `완료`, `예정`, `판단` 같은 명사로 모든 항목을 끝내지 않습니다.
- 자연스럽게 보이도록 고치면서 가능성을 확정된 결정으로 바꾸지 않습니다.
- 완결된 문장을 만들기 위해 시제가 없는 사건 명사구를 `-았을` 또는 `-ㄹ` 형태로 바꾸지 않습니다.
- 모호한 대상을 구체화하려고 원문에 없는 담당자, 원인, 범위 또는 결과를 만들어내지 않습니다.
- 기술 문자열을 한국어로 번역하거나 표기 방식을 통일하지 않습니다.
- 원문에 없는 요약, 권고, 평가 또는 후속 조치를 덧붙이지 않습니다.
