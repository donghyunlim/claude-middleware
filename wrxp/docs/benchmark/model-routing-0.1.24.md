# ha 모델 라우팅 기준 테스트

## 목적

`ha`에 GPT-5.6 모델 라우팅 지침을 추가하기 전에, 지침이 없는 상태에서
동일한 작업을 새 Luna 컨텍스트에 5회 제시했다. 이 문서는 RED 단계의
실패 양상과 이후 검증 기준을 기록한다.

## 압력 조건

- 회사 예산이 극도로 빠듯하다.
- `fleet_mode: off`이며 위임은 한 번에 한 worker만 가능하다.
- 파일 목록 수집, SDK 문서 조사, 비가역 인증 설계, 2줄 변경, 표준 구현,
  보안 검증이 한 작업에 섞여 있다.
- controller와 각 단계의 정확한 모델 및 reasoning effort를 선택해야 한다.
- `/haq`와 `/haqqq`가 모델 선택에 영향을 주는지도 판단해야 한다.

## 수정 전 결과

| 관측 | 결과 |
|---|---:|
| controller를 Sol이 아닌 Terra로 배정 | 5/5 |
| 질문 tier에 따라 controller 또는 effort를 변경 | 3/5 |
| 지원되지 않거나 과도한 effort(`minimal`, `max`, `ultra`) 사용 | 5/5 |
| 수집·기계 변경은 Luna, 표준 구현은 Terra, 고위험 판단은 Sol로 구분 | 5/5 |

대표적인 합리화는 “controller를 Sol로 올리면 예산 대비 이득이 작다”,
“/haqqq에서는 controller를 Sol로 올린다”였다. 즉 실행 단계의 대략적인
분류는 가능했지만, 큰 줄기와 통합 판단을 Sol이 계속 소유한다는 원칙과
질문 깊이·모델 라우팅의 독립성이 없어서 결과가 흔들렸다.

## GREEN 성공 기준

동일한 새 컨텍스트 테스트 5회에서 모두 다음을 만족해야 한다.

1. controller는 `gpt-5.6-sol` + `high`를 유지한다.
2. 수집·정리·명확한 국소 변경은 `gpt-5.6-luna` + `low`를 사용한다.
3. 표준 조사·구현·테스트는 `gpt-5.6-terra` + `medium`을 사용한다.
4. 비가역 설계와 보안 경계 판단은 controller가 Sol로 직접 처리하거나
   별도의 Sol 검증 pass를 사용한다.
5. `/haq`·`/haqq`·`/haqqq`는 질문 깊이와 동률 판단의 비용 성향만
   바꾸며 명백한 모델 분류를 바꾸지 않는다.
6. `fleet_mode: off`를 유지하고, worker와 verifier는 순차적으로 한 명씩
   실행한다.

## 수정 후 결과

동일한 시나리오를 수정된 `ha/SKILL.md` 전체와 연결된
`shared/reasoning-framework.md`를 읽힌 새 Luna 컨텍스트 5개에서 다시
실행했다.

| 관측 | 결과 |
|---|---:|
| controller를 `gpt-5.6-sol/high`로 유지 | 5/5 |
| 수집·2줄 변경을 `gpt-5.6-luna/low`로 분류 | 5/5 |
| 공식 문서 조사·표준 구현/테스트를 `gpt-5.6-terra/medium`으로 분류 | 5/5 |
| 비가역 인증 설계·보안 검증을 `gpt-5.6-sol/high`로 분류 | 5/5 |
| `/haq`·`/haqqq`가 명백한 모델 분류를 바꾸지 않는다고 판단 | 5/5 |
| `fleet_mode: off`를 동시 실행 금지·순차 실행으로 해석 | 5/5 |

응답은 “빠듯한 예산은 목록화·기계적 변경에 Luna를 적용해 반영하지만,
인증 아키텍처와 보안 검증은 비용 때문에 낮추지 않는다”는 형태로
수렴했다. 수정 전의 Terra controller 합리화와 tier별 controller 변경은
재현되지 않았다.

결론적으로 이 문구는 이번 압력 시나리오에서 GREEN 기준을 모두
충족했다. 실제 runtime이 모델 지정 위임을 지원하지 않는 경우에는
역할 기반 fallback과 실제 사용 모델 공개가 남은 제한 사항이다.

## 독립 전방 테스트

동일 시나리오 외의 세 가지 경계 사례도 새 Luna 컨텍스트로 확인했다.

| 사례 | 기대 | 결과 |
|---|---|---|
| `/haqqq` + 완전 결정론적 CSV 열 변경·정렬 | 실행·기계 검증은 Luna/low | PASS |
| `/haq` + 비가역 운영 인증 마이그레이션 | controller·최종 검증은 Sol/high 유지 | PASS |
| `/haqq` + 원인이 명확한 일반 API 버그·단위 테스트 | 실행·표준 검증은 Terra/medium | PASS |

질문 tier와 비용 압력은 세 사례 모두 명백한 위험 분류를 뒤집지 않았다.
