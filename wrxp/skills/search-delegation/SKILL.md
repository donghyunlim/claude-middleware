# Search Delegation

검색은 직접 수행하는 것이 기본이다. 이번 질문에 답하려면 여러 저장소·모듈·문서에 흩어진 대규모 지식을 넓게 탐색하고 압축해야 할 때만 위임한다. 작업자는 관련 후보를 선별하고 주 모델은 현재 판단에 필요한 발견과 근거를 읽는다.

## 적용 경계

- 시스템 전체의 크기가 아니라 이번 질문에 필요한 탐색 범위를 기준으로 판단한다. 로컬/Semble/MAGMA 같은 검색 수단이나 독립 질문 두 개가 있다는 사실만으로 위임하지 않는다.
- 대상·위치가 명확한 조회, 소수 파일 확인, 짧은 사실 확인과 이미 준비된 작은 자료는 직접 처리한다. 위치를 모른다는 이유만으로 대규모 탐색이라고 보지 않는다.
- 넓은 탐색을 위임했더라도 실제 변경을 좌우하는 중요한 조건과 충돌하는 근거는 주 모델이 직접 확인한다. 관련된 부분만 확인하며 전체 조사를 반복하지 않는다.
- 속도 개선이나 위임·상세 검색 비율을 보장하거나 할당하지 않는다. 사용자의 목적은 관련성 판단의 기준이지 원하는 결론에 증거를 맞추는 기준이 아니다.

## 검색 의뢰

파견 전에 [references/search-brief.md](references/search-brief.md)를 읽고 현재 대화와 정본에서 의뢰를 구성한다. 현재 작업·단계, 사용자 상황·목적, 이번 결정, 확정 제약·제외 범위, 기존 근거·공백, 담당 범위, 중요한 조건·반례, 종료 조건을 전달한다. 짧은 조사에는 간소화하며, 항목을 채우려고 이미 아는 내용을 다시 질문하지 않는다. 검색 방향을 바꾸는 사용자 소유 결정이 실제로 미정일 때만 묻는다.

공통 맥락은 한 번 작성하고 작업자별 담당 후보·질문만 바꾼다. 대화 전체나 관계없는 개인정보·자격 증명은 넘기지 않는다. 후속 조사에는 유효한 근거와 기존 의뢰를 재사용하고 변경점만 전달한다. 별도 기획서나 계획 전용 모델 호출을 추가하지 않는다.

작업자에게 질문에 필요한 자료 범위와 도구만 허용한다. 접근 제한이 실제로 강제되는지와 프롬프트상의 지시는 구분한다. 공급자 연결 실패는 상위 모델에 보고하며, 이를 해결하려고 홈 디렉터리·과거 세션·컴퓨터 상태로 탐색 범위를 넓히지 않는다.

## 검색 수단 선택

Semble은 검색 수단이고 이 스킬은 위임·인계 규칙이다. 둘을 별도 필수 단계로 연쇄 실행하지 않는다. Semble·MAGMA·직접 조회 중 선택이 필요하면 [references/search-routing.md](references/search-routing.md)를 읽는다. 의뢰에 대상 저장소·검색 수단·현재 체크아웃 또는 공급자 스냅숏을 함께 전달한다.

## 실행자와 분할

- 사용자 지정 모델과 환경의 기존 위임 정책을 우선한다. Codex에서 가용하면 Luna를 탐색 작업자 후보로 사용하고 Astra가 통합한다. Claude에서도 같은 의뢰·근거 계약을 사용하되, 기존 Codex 작업자 연결이 있으면 재사용하고 없으면 가용한 빠른 Claude 작업자를 선택한다. 별도 에이전트 체계를 중첩하거나 루틴 교차 검토 단계를 추가하지 않는다. 실제 도구 접근·모델 가용성을 확인하며, 다른 모델로 바꾸면 밝힌다. 위임 불가 시 직접 조사하거나 필요한 선택을 요청한다.
- 해당 실행 경로의 MCP 접근을 확인한 근거가 없으면 작은 검색·원문 조회로 연결부터 확인한다. 비대화형 실행은 기존 승인·인증 설정을 사용한다. 도구 미노출을 검색 미발견으로 취급하거나 승인 정책을 우회하지 않는다.
- 넓은 탐색은 독립 질문 축으로, 후보가 확보된 뒤에는 같은 스냅숏의 고유 파일·후보 ID로 분할한다. 청크 여러 개를 파일 여러 개로 세지 않는다. 호출자가 정한 후보 목록에서 중복 없이 배정하되 질문에 필요한 교차 참조는 허용한다.
- 페이지네이션은 실제 API가 지원할 때만 사용한다. 없으면 반환된 후보 목록을 나눈다. 작업자 수·페이지 크기·조회 개수를 고정하지 않고 독립 범위와 런타임 한도에 맞춘다. 작은 준비 자료는 직접 읽는 편이 나을 수 있다.

## 작업자의 반환 계약

의뢰의 이번 결정에 대응하여 다음을 짧게 반환한다.

1. **답과 중요한 발견:** 조건·예외·반대 근거를 보존하고, 관련 없는 후보는 중요한 제외 이유만 남긴다.
2. **근거:** 주장별 원문 참조와 확인 범위. 생성된 검색 설명, 실제 원문 확인, 추론을 구분한다. 파일을 열었다는 사실만으로 호출 경로나 운영 동작까지 확인했다고 하지 않는다.
3. **미확인 사항:** 공백이 어떤 판단에 영향을 주는지와 필요한 다음 조회. 충분하면 종료하며 전수 조사나 반복 조회를 자동 시작하지 않는다.

원본 위치·행 범위·SHA·조회 수치는 도구 기록에서 그대로 참조한다. evidence ID나 기계적 인계 기능이 실제로 있으면 사용하고, 없으면 원문 기록의 경로와 반환 메타데이터를 보존한다. 불투명 source_ref를 재조립하거나 누락된 수치를 추정하지 않는다. 이 스킬이 근거 추출기를 구현하거나 요약의 정확성을 자동 보증하지는 않는다.

## 주 모델의 통합과 종료

요약으로 다음 판단을 진행하고, 결론을 좌우하는 공백·충돌·의심스러운 근거만 재조회한다. 모든 원문을 다시 읽지 않으며, 높은 압축률만으로 품질 합격을 선언하지 않는다. 새 정책·승인 범위 변경은 사용자 판단으로 남긴다.

업무별 조사 지침을 유지한다. MAGMA에서는 search_magma의 설명을 후보로 사용하고 코드 결론은 read_source로 확인한다. 이 스킬은 MCP 확장, 환경 변경, 코드 구현이나 추가 에이전트의 재귀 파견을 승인하지 않는다. 검색을 매 개발 단계의 고정 선행 절차로 만들지 않는다.
