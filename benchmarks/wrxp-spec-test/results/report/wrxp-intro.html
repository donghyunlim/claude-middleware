이렇게 일합니다

질문 개수가 많아서가 아니라 순서가 달라서 결과가 달라집니다.

  1. 먼저 찾아봅니다

    요청, 첨부 파일, 저장소 문서, 데이터를 먼저 읽습니다. 확인할 수 있는 사실은 묻지 않습니다. 실행해 보면 알 수 있는 것도 직접 돌려 봅니다.

  2. 당신만 정할 수 있는 것만 묻습니다

    독자, 기준, 범위, 승인처럼 결과를 바꾸는 결정만 고릅니다. 나머지는 "따로 말씀 없으면 이렇게 하겠습니다"라고 기본값을 미리 보여 줍니다. 틀린 줄만 고쳐 주시면 됩니다.

  3. 실제로 확인하고 정직하게 보고합니다

    테스트와 실제 실행으로 확인한 것만 통과로 적습니다. 확인하지 못한 것은 확인하지 못했다고 씁니다. 되돌리기 어려운 작업 앞에서는 먼저 승인을 받습니다.

무엇을 부르면 되나요

모두 같은 엔진입니다. 달라지는 것은 작업 전에 확인할 결정의 양입니다.

명령이럴 때예시
/wrxp:ha할 일이 분명하고 바로 진행하면 될 때. 승인이 필요한 경계만 확인합니다."이 함수 off-by-one 고쳐 줘"
/wrxp:haq원하는 그림은 있는데 세부를 다 말하지 않았을 때. 한 번에 최대 4개를 묻습니다."주문 내역 엑셀로 뽑게 해 줘"
/wrxp:haqq정할 기준이 여러 개 얽혀 있을 때. 두 번까지 나눠 묻습니다."3분기 이탈률 이사회 보고용으로 구해 줘"
/wrxp:haqqq되돌리기 어렵거나 위험이 큰 일. 깊게 확인한 뒤 진행합니다."운영 DB 마이그레이션 안전한지 보고 진행해 줘"
/wrxp:setup처음 한 번. 전역 규칙을 설치해 답변 언어와 작업 원칙을 맞춥니다."양쪽 전역 지침에 wrxp 설정해 줘"

함께 따라오는 것들

승인 먼저

운영 DB 변경, 영구 삭제, 외부 공개처럼 되돌리기 어려운 일은 실행 전에 확인합니다. 실험에서 승인 없이 운영 DB를 바꾼 경우는 한 번도 없었습니다.

거짓 확인 없음

확인할 수 없는 환경에서 "확인했다"고 보고한 경우가 0건이었습니다. 확인하지 못한 것은 그렇다고 적습니다.

근거가 붙은 데이터

수치를 보고할 때 기간, 필터, 단위, 정의를 함께 적은 비율이 92~96%였습니다.

일관된 한국어

전역 설정을 켜면 한국어 질문에 언제나 한국어로, 명확한 문장으로 답합니다.

평소에는 그냥 요청하고, 기준이 머릿속에만 있는 일이면 앞에 /wrxp:haq나 /wrxp:haqq를 붙이세요.

첫 화면의 대화는 실제 실행 기록을 줄인 것입니다. 측정 조건: wrxp 0.1.78, Claude Opus 5.5, 2026-11-07. 숨은 의도를 아는 모의 사용자가 질문에 답하는 부서 업무 15종을 조건마다 4회 실행했습니다(총 360회). 업무 카드의 수치는 과제별 4회 평균이고, haq와 haqq 중 높은 쪽입니다. 모의 사용자가 묻지 않은 내용까지 답한 경우가 있어, 실제 사용자 환경의 효과는 이보다 작을 수 있습니다. 정답이 정해진 문제(표준 벤치마크, SWE-bench)에서는 조건 간 차이가 없었습니다. 측정 원자료는 저장소의 benchmarks/wrxp-spec-test 폴더에 있습니다.
