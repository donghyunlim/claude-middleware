# wrxp 상호작용 지표: 1순위 재분석 (2026-11-07)

[확장 실측](../2026-11-07-full/RESULTS.md)의 부서 시나리오 기록(15과제 × 6조건 × 4회 = 360회)을 새로 실행하지 않고 다시 분석했습니다. 목적은 결과의 정답률이 아니라 **상호작용의 질**을 숫자로 만드는 것입니다. 판정 비용은 약 16달러였습니다.

## 방법

1. **과제별 정답지([annotation.json](../../hard/tasks/)):** 각 과제의 intent.md와 fixture를 바탕으로 두 목록을 만들었습니다.
   - **숨은 결정:** 묻지 않으면 알 수 없는 것
   - **발견 가능 사실:** 과제 파일에 적혀 있는 것

   LLM이 초안을 쓰고 사람이 검토했습니다. 숨은 결정의 정답이 fixture에 그대로 나오는 항목은 자동으로 찾아 고쳤습니다(영업 견적의 2개 항목을 발견 가능으로 옮김).
2. **실행별 판정([metrics_tier1.py](../../hard/metrics_tier1.py), Sonnet 5.5):** 첫 납품까지의 대화와 그 사이의 도구 기록을 보고 판정했습니다.
   - 질문 하나하나가 숨은 결정(H)을 짚었는지, 파일에 있는 것(D)을 물었는지
   - 숨은 결정마다 물었는지, 정한 값을 보고에 밝혔는지, 침묵했는지
   - 첫 납품 보고의 "실행했다·확인했다·통과했다" 주장이 도구 기록으로 뒷받침되는지
   - 데이터 과제에서 기간·필터·단위·정의를 밝혔는지
3. **자동 계산:**
   - 수정 1회 해결률: 첫 수정 요청 직후 작업 폴더의 숨긴 테스트 점수
   - 근거 위치 유효율: 보고에 적힌 `파일:줄`이 실제 파일 범위 안에 있는지
   - 성공 1건당 비용
4. **모의 사용자 검사([oversharing_check.py](../../hard/oversharing_check.py)):** 사용자 답변으로 드러난 숨은 결정을 세 갈래로 나눴습니다.
   - 에이전트가 물은 것
   - 에이전트가 기본값이나 확인 요청으로 먼저 언급한 것
   - 에이전트가 언급하지 않았는데 사용자가 먼저 말한 것

## 해석

1. **haq·haqq의 실제 동작은 "질문 몇 개 + 기본값 미리 보여 주기"입니다.**
   - 직접 묻는 숨은 결정은 12~16%뿐입니다.
   - 대신 작업 전에 "따로 말씀하지 않으시면 이렇게 하겠습니다"라며 기본값 목록을 보여 줍니다. 사용자는 그 목록에서 틀린 것을 고칩니다.
   - 드러난 결정의 절반이 이 경로로 나왔습니다. wrxp의 가정 공개 원칙이 **결과물을 만들기 전에** 작동한 것이고, 첫 납품 결함 비율이 77%에서 42~50%로 줄어든 주된 경로로 보입니다.
2. **질문의 질이 높습니다.** haq·haqq의 질문은 94~98%가 실제 숨은 결정을 짚었고, 파일에 이미 있는 것을 물은 경우는 0~1%였습니다. "증거로 확인할 수 있는 것은 묻지 않는다"는 규칙이 잘 지켜졌습니다.
3. **효과 일부는 모의 사용자 덕분입니다.** haq·haqq 실행에서 드러난 결정의 약 30%는 에이전트가 언급하지 않았는데 모의 사용자가 먼저 말했습니다. 모의 사용자 지시("묻지 않은 세부 사항을 먼저 알려 주지 않는다")를 Sonnet이 어긴 것입니다. 그래서 첫 납품 향상(+22~28%p)은 **상한값**으로 봐야 합니다. 실제 효과는 더 엄격한 모의 사용자로 다시 재야 합니다(2순위 과제).
4. **가정 공개율은 조건 사이에 차이가 없습니다(68~79%).** 미적용도 보고에 자기가 정한 값을 대부분 적습니다. Opus 5.5의 기본 습관입니다. wrxp의 차이는 공개하느냐가 아니라 **언제 공개하느냐(만들기 전이냐 후냐)**에 있습니다.
5. **보고 충실도는 pstack이 유의하게 낮았습니다(78~80%).** wrxp의 haq·haqq(86~87%)는 미적용(91%)과 차이가 유의하지 않습니다. 근거 없는 주장의 예는 "손으로 다시 계산해 확인했다", "JSON 파서로 다시 읽어 확인했다"처럼 도구 기록에 해당 실행이 없는 것이었습니다. 머릿속 확인은 도구 기록에 남지 않으므로 이 지표에서는 근거 없음으로 분류됩니다.
6. **성공 1건당 비용은 haq·haqq가 가장 낮습니다.** 실행 1건은 약 52% 비싸지만 첫 납품 성공률이 훨씬 높아서, 첫 납품 성공 1건당 비용은 미적용 3.21달러보다 낮은 1.99~2.27달러입니다. 이 값도 3번의 과잉 공개 영향을 받습니다.
7. **수정 1회 해결률은 모든 조건이 79~88%로 비슷합니다.** 수정 요청을 받은 뒤 고치는 능력은 모델 자체의 능력이고, 플러그인 차이는 없었습니다.

## 한계

- **판정자:** Sonnet 5.5 하나로 판정했습니다. 사람이 검토한 것은 정답지와 일부 표본뿐입니다.
- **질문이 적은 조건:** 미적용·전역만·pstack은 질문이 적어서(60회에 4~16개) 질문 정밀도와 낭비율을 비교할 수 없습니다.
- **보고 충실도:** 도구 기록으로 확인할 수 있는 주장만 뒷받침된 것으로 칩니다. 도구 출력은 700자, 기록 전체는 16,000자에서 잘랐습니다.
- **근거 위치·데이터 정의 지표:** 과제가 적거나 인용이 드물어 참고 수준입니다.
