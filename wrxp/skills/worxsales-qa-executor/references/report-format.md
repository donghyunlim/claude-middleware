# 보고 형식: 사람이 읽는 층과 상세 층을 나누고, 글과 그림을 번호로 묶는다

## 행 페이지 구조 (publish_results.py가 만든다)
0. **🤖 자동 실행 결과** 제목: 이 제목부터 아래가 자동 생성 영역이다. 사람이 남기는 메모는 이 제목 위에 쓴다.
1. **결과 한눈에**: 판정 색의 강조 상자 하나. `판정 · headline`, 그 아래 `확인한 것`, `결과`, 필요하면 `재현 순서`.
2. **증거**: 그림마다 `그림 N. 캡션` → 확대 캡처(있으면) → 전체 화면 캡처 → 번호표 설명 목록(`① …`).
3. **상세 기록 (개발자용)**: 접힌 토글. 판정 근거, 실행 환경, 액션·관찰값, 이름 대응, 시나리오 문제, 행 범위 밖 관찰.
4. **이전 실행 기록**: 같은 TC의 예전 결과 한 줄씩, 접힌 토글.

DB 목록의 「최근 요약」에는 headline이 들어가므로, headline만 읽어도 무슨 일이 있었는지 알 수 있어야 한다.

## 글쓰기 규칙
- headline·checked·outcome은 기획자·영업 담당자가 읽는다. 문서 ID(7-AC03), 컴포넌트명, CSS, 좌표를 쓰지 않는다. 그런 내용은 details에 둔다.
- 화면에 보이는 이름을 「」로 쓴다. 시나리오의 이름과 달랐다면 앱의 이름을 쓰고, 대응은 details.name_mismatches에 둔다.
- 「OK」도 무엇을 확인했는지 한 문장으로 남긴다. "정상 동작"만 쓰지 않는다.
- 「미구현」은 무엇이 없는지(버튼·항목·「준비 중」 화면)를 쓴다.
- 「실행 불가」는 무엇이 없어서 못 했는지(데이터·권한·환경)와 필요한 것을 쓴다.

## 번호 박스 규칙
- 박스는 판정에 쓴 요소에만 그린다. 그림 한 장에 1~3개.
- 숫자 번호표(①②③)는 **재현 순서의 단계 번호**다. 그림의 ②는 repro의 ② 단계 장면이어야 한다. 단계와 무관한 보조 표시(예: 메모를 입력한 탭, 그대로 유지된 활성 탭)는 알파벳 번호표(Ⓐ Ⓑ, marks의 `n`을 `"A"`, `"B"`로)로 쓴다. 알파벳은 그림마다 다시 시작하지 않고 행 전체에서 이어 쓴다(그림 1에 Ⓐ, 그림 2에 Ⓑ). 같은 요소를 여러 그림에서 가리키면 같은 기호를 다시 쓴다.
- 번호표는 박스의 오른쪽 위 모서리에 걸쳐 붙는다. 그래도 판정에 필요한 글자를 가리면 박스 대상을 한 단계 큰 영역(행·카드)으로 바꿔 다시 찍는다.
- repro가 없는 판정(OK·미구현 등)에서는 그림의 번호표를 ①부터 쓰고, 「결과」 문장에서 같은 번호로 가리킨다.
- 같은 이름의 요소가 여러 곳(사이드바 메뉴·화면 탭)에 있으면 `scope`(기본 "page" = 활성 작업 화면)로 좁히고, 캡처를 열어 박스 위치를 눈으로 확인한다. 엉뚱한 곳에 그려졌으면 다시 찍는다.
- `mark`가 확대 캡처(`-zoom.png`)를 만들면 그림의 `zoom`에 넣는다. 확대 캡처가 먼저 보이고 전체 화면이 뒤에 온다.
- 개인정보(전화번호·이메일·주소)가 크게 찍힌 확대 캡처는 쓰지 않는다. 화면에 이미 마스킹된 값은 그대로 둔다.
