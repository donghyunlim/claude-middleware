# wrxp setup

플러그인이 스킬 본문을 제공하고, 전역 지침에는 짧은 연결 규칙만 둔다. 개인 지침을 복제하거나 스킬마다 전역 파일을 추가하지 않는다. 셋업은 사용자가 요청했을 때 실행하며 플러그인 설치만으로 전역 파일을 몰래 수정하는 훅은 만들지 않는다.

공통 배포본은 다른 플러그인과의 우선순위를 지정하지 않는다. 특정 사용자가 선택한 wrxp 우선 규칙은 그 사용자의 개인 지침에만 유지한다. Sol 위임·자체 검증 규칙은 그대로 추가하며, 기존 지침과 방식이 다르다는 이유만으로 셋업을 중단하거나 일괄 선택을 요구하지 않는다. 파일을 수정할 구역의 식별은 별도의 문제다.

## 대상과 사전 확인

1. 요청에서 대상 런타임(Codex, Claude, 양쪽)과 설치·갱신·점검·제거 중 작업을 정한다. 지정이 없으면 설치 상태를 확인하고 필요한 선택만 한 번 묻는다. 사용하지 않는 런타임의 디렉터리를 만들지 않는다.
2. [references/runtime-setup.md](references/runtime-setup.md)를 읽고 선택한 런타임에서 wrxp가 설치·활성화되어 있는지 확인한다. 없는 쪽에 설치하는 것은 사용자의 셋업 범위에 포함될 때만 수행한다. CLI 설치·계정 로그인·MCP 인증은 별도이며 임의로 실행하거나 비밀값을 복사하지 않는다.
3. [assets/global-rules.md](assets/global-rules.md)의 연결 규칙과 대상 전역 파일을 확인한다. 포함된 모든 스킬은 플러그인에서 제공한다. 자주 쓰는 개발·테스트·검색·코드 위임은 조건부 연결하고, 명령형 스킬은 선택 용도만 안내한다. `handoff`의 명시 호출 제한을 유지한다.
4. Python 3.9 이상이 있는지 확인한다. 코드 위임에는 Sol medium/high를 실제로 실행할 수 있는 경로가 필요하다. Claude만 설치되어 있거나 모델 접근이 없으면 코드 위임을 '준비 미완료'로 보고한다. 코드 위임을 사용할 수 없어도 다른 스킬 연결은 설치할 수 있다. 검색 도구·Semble·MAGMA·Qwen은 선택 기능이며 없다고 자동 설치하지 않는다.

## 미리보기 → 적용 → 확인

`<skill-dir>`은 이 SKILL.md가 있는 실제 디렉터리다. 버전별 플러그인 캐시 경로를 전역 지침에 고정하지 않는다.

```sh
python3 "<skill-dir>/scripts/setup_global.py" --target both
python3 "<skill-dir>/scripts/setup_global.py" --target both --apply
python3 "<skill-dir>/scripts/setup_global.py" --target both --check
```

- 기본 실행은 읽기 전용이다. `--target codex` 또는 `--target claude`로 범위를 줄이고, 다른 프로필은 `--codex-home`·`--claude-home`으로 명시한다. 기본 경로는 `CODEX_HOME`/`CLAUDE_CONFIG_DIR`, 없으면 사용자의 `.codex`/`.claude`다.
- 미리보기에 나온 대상 경로·wrxp 규칙·기존 규칙과의 충돌·미충족 기능을 짧게 보여준다. 해당 대상의 설치·갱신을 이미 명확히 요청받았다면 중복 승인 없이 적용한다. 대상 확대나 기존 개인 규칙 제거가 필요하면 먼저 묻는다. 점검만 요청했다면 `--apply`를 실행하지 않는다.
- 도구는 식별 가능한 자체 관리 구역만 갱신한다. 기존 파일을 변경할 때는 인접한 고유 백업을 남기며 재실행 시 같은 내용은 쓰지 않는다. `--check`는 최신이면 0, 변경이 필요하면 1, 오류면 2다. 이 결과는 파일 설치 상태이며 런타임에서 스킬이 실제 로드되었다는 증거가 아니다.
- 기존의 수동 wrxp 규칙, OMC 구역, 다른 플러그인 설정은 도구가 지우지 않는다. 관리 구역 밖에 동일 규칙이 있으면 중복을 알리고, 정확한 문구와 제거 범위를 승인받은 경우에만 백업 후 별도로 정리한다. 언어·문체, 개인 경로, 업무 데이터, 자격 증명, 메인 모델·권한 설정은 가져오지 않는다.
- 깨진 마커·중복·중첩 때문에 기존 관리 구역을 식별하기 어려워도 설치 전체를 중단하지 않는다. 원문은 바이트 단위로 보존하고 새 규칙만 별도로 추가한다. 문서 예시 안의 마커를 실제 설치 구역으로 사용하지 않는다. 이후 갱신·제거도 실행기가 안전하게 식별하는 추가분만 대상으로 한다. 모호한 기존 규칙이 남았다는 경고를 숨기지 않는다.
- 추가 구역에는 `WRXP-INSTALLER` 경계와 길이·해시 식별 기록을 남긴다. 이 기록이나 본문이 손상되면 임의로 복구·삭제하지 않고 기존 내용으로 보존한다. `appended`는 보존 후 추가, `unmanaged_rules: true`는 모호한 기존 구역이 남았다는 뜻이다. 제거 결과가 `removed_unmanaged` 또는 `unmanaged`이면 완전 제거로 보고하지 않는다. 전체 Markdown·HTML 문법을 검증하는 도구는 아니다.
- 심볼릭 링크, 잘못된 파일 인코딩, 권한 오류, 동시 변경 등 실제 파일 접근 문제가 있으면 해당 경로와 원인을 보고한다. 관리 구역이 모호할 때의 추가 방식으로 이 오류를 우회하지 않는다. 양쪽 적용 중 쓰기 오류가 나면 성공한 대상과 실패한 대상을 구분한다.

## 갱신과 제거

플러그인 업데이트 뒤 같은 명령을 실행하면 현재 배포본의 규칙으로 식별 가능한 관리 구역만 갱신한다. 새 기능은 설치된 스킬 목록과 비교하되 전역 설명을 계속 늘리지 않는다. 제거는 먼저 `--remove`로 미리 보고, 승인된 대상에 `--remove --apply`를 실행한다. 안전하게 식별한 추가분만 제거하며, 모호한 기존 규칙은 남겨 두고 그 사실을 알린다. 남은 규칙이 있으면 완전히 제거했다고 보고하지 않는다. 사용자 파일·플러그인·백업은 삭제하지 않는다.

## 완료 보고

대상별 경로·변경 여부·백업 위치, 포함된 스킬 수, 준비되지 않은 실행 경로를 보고한다. 스킬 목록은 동봉 파일 목록과 런타임에서 보이는 목록을 구분한다. 기존 설정을 그대로 보존했는지 알리고, Codex는 새 대화, Claude는 재시작 후 `wrxp:setup`과 주요 스킬이 보이는지 확인하도록 안내한다. 모델 호출·실제 개발로 검증 범위를 자동 확대하지 않는다.
