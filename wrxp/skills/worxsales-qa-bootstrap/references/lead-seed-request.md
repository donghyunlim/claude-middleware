QA 계정의 DEV 리드가 0건이면 리드 시나리오가 「실행 불가」로 남습니다. 리드 원천은 MAGMA DEV DB이고 QA나 조회 도구로는 쓸 수 없으므로, **MAGMA DEV 쓰기 권한자(DBA 또는 MAGMA 담당 팀)** 에게 아래 내용을 보냅니다. 표와 경로는 2026-10 develop 기준입니다. 보내기 전에 백엔드 저장소에서 리드 조회 조건을 다시 확인해 경로·코드 값을 고칩니다(`packages/integrations/magma-read/src/lead-read-specs.ts`, `leads.policy.ts`, `leads.service.ts`).

자리표시자: `<사번>`(QA 계정 사번), `<이름>`, `<본인 메일>`(사용자 본인 주소, plus 주소 가능), `<부서 코드>`, `<시작일>`(백엔드 설정 `WS_LEAD_POPULATION_START_DATE`).

# DEV 신규가입 리드 테스트 데이터 요청

QA 계정 <이름>(사번 <사번>)의 DEV 리드가 0건이라 리드 관련 시나리오 N행이 「실행 불가」입니다. 아래 순서로 테스트 리드를 넣어 주십시오. 공식 생성 프로시저가 있으면 그쪽을 먼저 써 주십시오.

## 백엔드가 리드를 읽는 조건
- 원천: JK `dbo.REP_JK_MEM_GROUP_MOVE_HIST`, AM `dbo.REP_AM_MEM_GROUP_MOVE_HIST`
- 이동 사유 코드: JK 80·81·82, AM 83·84·85
- `Reg_Dt >= <시작일>`, 영업자 조회는 `After_Rep_Emp_Code = <사번>`
- 리드 인정: `CST_MEM` 행이 있고 사업자번호가 비어 있지 않음
- IN 판정: 탈퇴 아님, `REP_*_MEM`·`REP_*_MEM_GROUP` 행 있음, 그룹 담당 = `After_Rep_Emp_Code`

## 순서
0. 읽기 확인: 사원 행(`dbo.EMP`), 이동 사유 코드, 대상 표의 열·트리거
1. 회원: DEV의 테스트 기업회원(사업자번호 있음, 탈퇴 아님) JK 5명·AM 5명. 연락처는 원래 값을 백업한 뒤 `QA-` 이름, 사용하지 않는 번호, `<본인 메일>`로 바꿉니다(실제 고객에게 연락이 가지 않도록).
2. 그룹: 회원마다 단독 그룹을 새로 만들어 담당을 `<사번>`으로 둡니다. 원래 그룹과 담당 값을 백업합니다.
3. 리드 원천 행: 회원마다 이동 이력 1행(사유 JK 80 또는 AM 83, 등록일 = 지금, 메모 `QA-LEAD-SEED`). 만든 이력 번호를 QA에 알려 주십시오.
4. 확인: WorxSales DEV 리드 목록(<이름>)에 JK 5건이 보이는지 확인합니다.

## 정리
이동 이력 삭제 → `REP_*_MEM` 원복 → 새 그룹 삭제 → 연락처 원복. QA가 리드 판정을 저장했다면 WorxSales DB의 판정 행과 MAGMA DEV의 이동 요청도 정리합니다.

## 위험
- QA가 부적격(Unqualified)을 저장하면 MAGMA DEV에 이동 요청이 생겨 DEV 결재자에게 보일 수 있습니다.
- MAGMA DEV 배치가 새 그룹을 건드릴 수 있습니다(0단계에서 트리거·배치 확인).
