# 변경 항목 처리표

첫 실행(이전 크롤 없음)에서는 `discovered_new`와 `external_links_new`를 확인 항목으로 올리지 않고 `baseline_*` 목록으로만 남깁니다. 처음에는 모든 것이 「새것」으로 보이기 때문입니다. 두 번째 실행부터는 기준 목록에 없던 것만 올라옵니다.

`diff_sources.py`가 내는 항목과 처리 방법입니다. 어떤 항목도 「아마 괜찮다」로 넘기지 않습니다. 처리하지 않을 항목은 사용자 결정을 받아 `watch.json`의 `ignore`에 `"<page_id>": "<이유>"`로 적습니다.

| 항목 | 뜻 | 처리 |
|---|---|---|
| `added` | 지난 크롤에 없던 페이지 | 3단계에서 로컬 사본을 만들고, 4단계에서 해당 화면의 시나리오를 새로 씁니다 |
| `removed` | 지난 크롤에 있었는데 이번에 없음 | 이동인지 삭제인지 확인합니다. 삭제면 해당 화면 행을 「범위 제외」로 바꿉니다 |
| `renamed` | 제목이 바뀜 | 「[제거]」 같은 표시가 붙었는지 봅니다. 제거면 범위 제외, 아니면 파일 이름만 바뀝니다 |
| `moved` | 상위 페이지가 바뀜 | 다른 메뉴로 옮겨졌으면 시나리오의 메뉴·화면 칸을 확인합니다 |
| `edited` | 본문이 바뀜 | 이전 사본(`_snapshot_<날짜>`)과 비교해 바뀐 규칙만 시나리오에 반영합니다 |
| `archived` | 페이지가 보관 상태 | `removed`와 같게 처리합니다 |
| `errors` | 열 수 없는 페이지(대개 integration 공유 누락) | 사용자에게 알리고 공유를 요청합니다. 그 페이지의 변경은 확인되지 않은 상태로 보고합니다 |
| `local_missing` | 크롤에는 있는데 로컬 사본이 없음 | 3단계에서 가장 가까운 상위 페이지의 폴더에 만듭니다. 상위가 없으면 `_unmapped/`. 첫 실행에서 정책 결정 DB 59행과 기능정의서 최상위 안내·변경 요약 11페이지가 여기에 걸렸습니다. 예전 `fetch_spec.py`가 DB 행을 받지 않았기 때문입니다. 새로 받은 원천이 기존 행의 기대결과에 영향을 주는지 4단계에서 확인합니다 |
| `local_orphan` | 로컬 파일의 페이지가 크롤에 없음 | `_stale/`로 옮기고, 그 파일을 근거로 쓴 행을 확인합니다 |
| `local_stale` | 로컬 사본의 본문이 크롤과 다름 | 3단계에서 교체합니다(옛 파일은 스냅샷) |
| `local_duplicate` | 같은 페이지의 로컬 파일이 둘 이상 | 제목이 바뀌기 전 파일이 남은 경우입니다. 옛 이름 파일을 `_stale/`로 옮깁니다 |
| `mockup` | 목업 파일에 새 버전이 붙었거나, 최신 버전이 쓰던 버전보다 높음 | 3단계에서 받고, 쓰던 버전 텍스트와 비교해 바뀐 화면을 적습니다 |
| `discovered_new` | 상위 작업 공간에서 키워드(목업·정의서·권한 등)에 맞는 새 페이지·DB | 열어서 원천인지 판단합니다. 원천이면 `watch.json` 루트에 추가하고 다시 크롤합니다 |
| `external_links_new` | 크롤 범위 밖 페이지로 가는 새 링크 | 원천 내용이 링크된 페이지로 옮겨졌는지 확인합니다. 그렇다면 루트에 추가합니다 |

## 목업 버전 비교

- 파일 이름 규칙은 `watch.json`의 `mockup.pattern`입니다. 버전은 숫자 튜플로 비교합니다(1.10 > 1.9).
- 새 버전 텍스트(`sources/_mockups/<이름>.txt`)와 쓰던 버전 텍스트를 `diff`로 비교하고, 화면 제목 단위로 바뀐 곳을 보고에 적습니다. 쓰던 버전 파일이 없으면 `apply_sources.py`가 함께 받습니다.
- 목업은 화면 대부분이 스크립트 안에 있는 단일 페이지 앱입니다(8MB 안팎). 그래서 텍스트 파일은 보이는 글자 뒤에 `## script strings` 줄을 두고, 스크립트의 한국어 문자열을 처음 나온 순서대로 한 줄씩 담습니다. 태그만 걷어 내면 37줄만 남아 비교가 되지 않습니다(2026-10-10 v1.7↔v1.9 실제 사례: 문자열 추가 645, 삭제 291).
- 차이가 크면 메뉴·화면별 분류(「기능정의서에 이미 반영」, 「기능정의서와 다름」, 「기능정의서에 없음」)를 에이전트에게 맡기고, 결과를 `sources/_mockups/diff_v<옛>_v<새>.md`에 둡니다.
- 목업 변경만으로 기능정의서와 다른 기대결과를 만들지 않습니다. 기능정의서가 아직 따라오지 않았으면 「기획서와 목업이 다름」을 보고에 남깁니다.
