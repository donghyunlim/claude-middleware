# Code delegation

## 적용 범위

기존에 합의된 요구·기획을 재사용하여 독립적인 구현 단위를 위임한다. 위임만을 위해 기획서를 새로 쓰거나 승인된 결정을 다시 묻지 않는다. 작은 수정은 직접 처리하고, 불명확한 사용자 경험·업무 규칙·모듈 계약은 메인 에이전트가 먼저 정리한다. 중·대규모 개발에서는 `wrxp:staged-development`의 현재 단계와 정본을 유지한다.

이미 구현을 위임받은 작업자는 이 스킬을 다시 적용하여 재위임하지 않는다. 맡은 구현과 필요한 자체 검증을 직접 수행한다.

## 모델과 실행 경로

- 코드 작업자는 **`gpt-6.1-sol`**을 사용한다. 기본 사고 수준은 **`medium`**이며, 복잡한 상태 전이·동시성·여러 모듈의 계약을 다루는 경우 AI가 **`high`**를 선택하고 이유를 짧게 기록한다.
- 허용 선택지는 `medium`과 `high`뿐이다. `low`를 포함한 다른 수준, 사고 수준 생략, Terra/Luna 또는 런타임 기본 모델로의 무단 폴백은 금지한다. 이 제한은 코드 위임에 적용하며 검색·문서·메인 모델의 설정을 바꾸지 않는다.
- 네이티브 위임 도구가 해당 모델과 사고 수준을 모두 지원할 때만 사용한다. 지원하지 않으면 설치된 Codex CLI나 두 값을 명시적으로 고정할 수 있는 검증된 연결 경로를 사용한다. Claude의 `Agent.model`에 OpenAI 모델 ID를 넣지 않는다.
- Codex CLI 예시: `codex exec -C <approved-workdir> -m gpt-6.1-sol -c 'model_reasoning_effort="medium"' -`. 작업 지시는 표준 입력으로 전달한다. `high`를 선택했다면 해당 값만 바꾼다. 기존 사용자 설정·권한·격리를 유지하며 우회 옵션을 추가하지 않는다.
- 실제 실행 모델과 사고 수준을 확인할 수 있는 실행 기록을 남긴다. 지원 오류·용량 제한으로 실행할 수 없으면 그 사실을 보고하고 대안을 협의한다. 공급자 오류를 구현 품질 실패로 집계하거나 모델을 몰래 바꾸지 않는다.

## 인계할 내용

필요한 내용을 짧게 구조화한다. 기존 정본·파일을 가리키고 전체 대화를 복사하지 않는다.

1. 현재 작업의 목적·상태, 정본 경로와 현재 단계.
2. 맡길 구현, 담당 파일·경계, 변경하면 안 되는 동작. 다른 작업자의 변경을 되돌리지 않도록 명시한다.
3. 합격 조건과 관련 검사 명령, 브라우저·개발/프로덕션 모드 등 결과를 바꾸는 실행 환경.
4. 허용 범위·작업 상한, 메인에게 돌려보낼 미결정 사항. 작업자에게는 직접 구현·자체 검증하는 역할임을 명시한다.

여러 작업자는 파일 소유권과 의존성이 분리될 때만 병렬 실행한다. 단순히 더 많은 에이전트를 쓰기 위해 작업을 분할하지 않는다.

## 작업자의 구현과 자체 검증

작업자가 구현과 필요한 테스트를 함께 책임진다. 검사는 합격 조건·변경 위험에 맞추고, 기존 프로젝트 명령으로 실행한다. 별도 테스트 모델을 자동으로 추가하지 않는다. 기대 결과를 구현에 맞춰 약화하지 않는다.

검증 근거에는 명령, 종료 코드, 로그 위치, 검사한 소스 버전과 관련 환경을 남긴다. 검사 후 관련 코드·테스트·의존성·환경이 바뀌면 기존 통과 결과를 재사용하지 않고 영향을 받는 검사만 다시 실행한다. 선택한 파일의 해시는 전체 의존성의 동일성을 증명하지 않는다.

작업자는 실제 모델·사고 수준, 변경 파일, 합격 조건별 결과, 현재 코드에 대응하는 검증 근거, 남은 위험·미확인 사항을 반환한다. 합의된 범위를 넘는 결정은 메인에게 돌려보낸다.

## 메인의 수용과 종료

메인은 합격 조건과 인계 근거를 대조한다. 현재 코드에 대응하는 충분한 자체 검증 근거가 있으면 수용하며, 위임했다는 이유만으로 Astra의 전체 재검토·재구현·동일 테스트 반복을 추가하지 않는다.

사용자가 별도 리뷰를 요청했거나, 보안·권한·데이터 손실·통합 충돌·근거 누락 같은 구체적 위험이 있으면 해당 부분만 추가 확인한다. 병렬 결과를 합친 뒤 새로 발생한 통합 위험도 여기에 포함된다. 이 규칙은 필수 프로젝트 검사나 사용자 요청 리뷰를 생략하는 근거가 아니다.

이 계약은 wrxp 코드 위임의 실행 방식을 정의하며, 다른 플러그인과의 우선순위를 선언하지 않는다. 사용자 승인·실행 권한·단계 경계는 확대하지 않는다.
