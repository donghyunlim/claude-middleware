# Changelog

이 문서는 wrxp 플러그인의 사용자에게 영향을 주는 변경 사항을 기록합니다.

## [0.1.76] - 2026-10-29

- **`fast-worker` 에이전트와 로컬 Qwen 의존을 없앴습니다.** `agents/fast-worker.md`, `scripts/qwen.py`, `docs/fast-worker-routing.md`를 지웠습니다. 단순 작업은 `ha` 모델 라우팅의 단순 작업자 역할(Claude는 Haiku, Codex는 `gpt-6-luna`)이 맡고, 합의된 코드 구현은 전처럼 `code-delegation`이 맡습니다. 개인 환경에 `~/.claude/scripts/qwen.py` 같은 연결을 따로 두었다면 지워도 됩니다.
- `haq`·`haqq`·`haqqq`: 중첩 호출이 없는 런타임에서도 `ha`의 참조 파일을 한꺼번에 읽지 않고, `/ha`와 같은 시점(질문할 때, 모델을 정할 때, 무거운 경로에 들어갈 때)에만 읽습니다.
- `ha`: 최종 답 틀(`result`)을 `references/verification.md`에서 `SKILL.md` 본문으로 옮겼습니다. 이제 가벼운 경로에서도 항상 읽히며, 사용자에게는 키 이름 대신 문장과 목록으로 씁니다.
- `intent-anchor`: 자동 실행 조건 목록의 깨진 형식을 고치고, Codex 메인일 때 리뷰어가 Astra가 없으면 Sol로 내려간다는 실제 동작을 적었습니다.
- 플러그인·마켓플레이스 설명과 README 배지를 현재 구성에 맞게 고쳤습니다.

## [0.1.75] - 2026-10-28

- **팀원 안내: 전역 지침 블록에 "한국어 출력 원칙"이 들어갔습니다.** 주체·대상을 생략하지 않기, 조사·어미 갖추기, 완결된 문장, 정확한 어휘, 기술 용어 표기, 코드·로그 원문 유지 등 11줄과, 완성된 한국어 산출물은 `wrxp:korean-polish`로 교정한다는 안내입니다. Claude와 Codex 모두 `/wrxp:setup`(Codex는 `$wrxp:setup`)으로 갱신하십시오. 엠대시 사용 줄은 개인 취향이라 넣지 않았습니다.

## [0.1.74] - 2026-10-28

- **팀원 안내: `staged-development` 적용 범위가 좁아졌습니다.** 이제 크거나 되돌리기 어려운 개발, 또는 제품 방향이 정해지지 않은 작업에만 씁니다. "중간 규모 개발"은 더 이상 자동 적용 대상이 아닙니다. 전역 지침 블록의 Development·Coding·Intent drift 줄이 바뀌었으니 `/wrxp:setup`으로 갱신하십시오. Coding 줄에는 공유 계약을 바꾸면 새 맥락 sonnet 검토를 붙이는 예외가 들어갔습니다.
- `ha`: 트랙(버그, 기능, 조사, 글쓰기·기획서, 데이터·수치, 리팩터링, 프로토타입, 맞춤 절차)과 `references/tracks.md`를 더했습니다. 평소 절차는 모델이 판단하고, 되돌리기 어려운 변경·외부 공개, 재발 버그, 사용자 지정일 때만 무거운 경로를 따릅니다. 공유 계약 변경은 무거운 경로 대신 새 맥락 검토 1회만 붙습니다.
- 질문 계약: 해 보면 관찰되는 사실은 `experiment`로 묻지 않고 확인합니다. 요청에 정해지지 않은 취향·제품 판단(`mid_run_decision`)은 그 판단이 드러난 시점에 남은 구현이 5분 이상 걸릴 것 같으면 `/ha`에서도 그 판단에 기대는 작업 전에 묻고, 그보다 작으면 정한 뒤 `defaults_taken`으로 답 첫머리에 알립니다. 위임 전 사전 질문, 개요 확인, 프로토타입 전환, 같은 패턴 함께 고치기는 시간과 관계없이 묻습니다. ha의 참조 문서는 질문할 때, 하위 에이전트에 모델을 지정할 때, 무거운 경로에 들어갈 때만 읽습니다. 같은 모델 작업자에게는 메인 맥락이 넘칠 만큼 큰 작업만 넘깁니다. 전역 블록에 "사용자가 쓴 언어로 답한다"를 넣었습니다.
- 검증: 대체물로 확인한 것은 통과가 아니며 `inconclusive`로 보고합니다. 공유 계약을 바꾸면 새 맥락 검토(Claude sonnet, Codex `gpt-6.1-sol` `high`)를 1회 붙입니다. task-type 검증 표는 트랙별 확인으로 대체했습니다.
- `code-delegation`: 작업자 지시문 핵심 줄, 쓰기 작업자 병렬 금지, 멈춘 작업자 이어 쓰기, `git diff --stat` 기반 보고 확인을 더했습니다.
- `intent-anchor`: 재시도가 쌓였다는 이유만으로는 자동 실행하지 않습니다. 전역 지침 블록의 Intent drift 줄도 바뀌었습니다.
- 새 공유 규칙 `shared/writing-rules.md`와 한국어 최종 교정 skill `korean-polish`를 더했습니다. 같은 이름의 개인 사본이 있으면 지워도 되며, `/wrxp:setup` 점검이 이를 알려 줍니다. `handoff` 문서에는 이어받는 세션이 결정·완료 주장을 원 기록과 실제 결과로 확인하라는 줄이 들어갑니다.
- `setup`: 플러그인과 같은 이름의 개인 skill이 `~/.claude/skills/`나 `~/.codex/skills/`에 있으면 알립니다. 지우지는 않습니다.

- QA 조율: 슬롯 점검·재로그인(`slots.sh`), 묶음 감사(`audit_batch.py`), raw CDP 도구(`cdp_tab.mjs`)를 더했습니다. `qa_rollout.sh`는 모든 슬롯에 자기 사용자 데이터 폴더를 쓰고 지워진 슬롯 설정 폴더를 다시 만듭니다. `merge_reverify.py`는 재검증 「시나리오 문제」를 「보류-기록」으로 합칩니다. `launch_app.sh`는 자기 포트의 앱만 다시 띄웁니다.
- 쓰기 범위, 본인 대상 발송·쓰기의 이중 확인, 직접 만드는 사전조건, 역할 부여 순차 단계와 복원 확인, 멈춘 작업자 깨우기, 감사 뒤 게시, 결과 분류 보고 규칙을 문서에 반영했습니다.

## [0.1.50] - 2026-10-10

- `worxsales-qa-refresh` 첫 실제 실행에서 찾은 문제를 고쳤습니다.
  - 정책 결정 DB처럼 DB 행으로 된 원천은 결정 상태를 속성에 둡니다. 이제 속성을 `[속성] 이름: 값` 줄로 본문과 비교 해시에 넣어, 상태만 「결정 완료」로 바뀌어도 변경으로 잡습니다. 속성 줄이 없는 사본은 오래된 사본으로 봅니다.
  - 제목만 훑는 탐색이 이미 끝까지 읽은 페이지 기록을 덮어써 메뉴 페이지가 빠지던 문제를 고쳤습니다. 탐색은 트리 루트에서 멈추고, 레이아웃 블록만 3단계까지 엽니다.
