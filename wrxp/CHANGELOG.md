# Changelog

이 문서는 wrxp 플러그인의 사용자에게 영향을 주는 변경 사항을 기록합니다.

## [0.1.27] - 2026-09-04

### Fixed

- `/haq`·`/haqq`·`/haqqq`가 질문할 결정이 있는데도 질문 없이 실행하던 문제를 고쳤습니다. 질문 적격성 판정에 필요한 계약이 참조 문서 45KB 안에만 있어, 참조 로드가 누락되면 질문 정책이 통째로 적용되지 않았습니다. 이제 `QuestionGate` 계약을 네 진입 파일에 직접 두어 참조 문서를 읽지 못해도 판정을 건너뛸 수 없습니다.
- 공통 reasoning framework가 "사용자에게 묻는 것은 최후 수단"이라고 지시해 질문을 억제하던 문제를 고쳤습니다. 이 원칙은 증거로 확인할 수 있는 사실에만 적용되며, 승인·비공개 정책·의도처럼 사용자만 소유한 결정과 산출물의 독자·공유 범위·결정 권한을 바꾸는 선택에는 적용하지 않습니다.
- 런타임 기본 설정이 질문보다 가정을 선호하도록 안내하는 환경에서 질문 tier가 무력화되던 문제를 고쳤습니다. Codex의 Default collaboration mode가 이에 해당합니다. 질문 tier 스킬을 호출한 것 자체가 명확화를 요청하는 명시적 사용자 지시이므로, `must_ask`와 예산 안의 `decision_quality` 질문이 런타임 기본 선호보다 우선합니다.

### Changed

- 참조 문서를 필요한 시점에만 읽도록 바꿨습니다. `questioning.md`는 판정 결과가 `ask`일 때, `model-routing.md`는 첫 위임 전에, `verification.md`는 검증 기준을 정할 때 읽습니다.
- 질문 예산 산식과 카운터 갱신 규칙을 `questioning.md` 한 곳으로 모으고, 진입 파일에서 중복 기술을 제거했습니다.
- 판정 결과를 `ask`, `pass_zero`, `blocked` 세 가지로 명시했습니다. `pass_zero`는 후보를 실제로 평가한 결과가 0개일 때만 유효하며, 평가를 건너뛴 상태는 `pass_zero`가 아닙니다. 적격 후보가 없을 때 0문항으로 진행하는 기존 동작은 그대로입니다.

## [0.1.26] - 2026-09-03

### Changed

- 직접 `/ha`는 선제 discovery 질문을 하지 않고, 승인·보안·비밀·외부 변경·파괴적·불가역 경계만 즉시 확인하도록 조정했습니다. 질문 tier인 `/haq`·`/haqq`·`/haqqq`의 상한은 유지합니다.
- Knife family는 고정 직렬 실행 대신, 런타임이 공개한 동시 위임 한도 안에서 하나의 확정 의도를 dependency task graph로 실행합니다. 같은 파일·공유 상태·외부 부작용·생산자→소비자·writer→verifier 의존은 순차 wave로 유지합니다.
- `/cast`는 task 단위 병렬화와 구분되는 관점·가설 fleet에 사용하도록 역할을 명확히 했습니다.
- Codex와 Claude Code의 설치·업데이트 명령을 현재 marketplace 흐름으로 갱신했습니다.

## [0.1.25] - 2026-09-03

### Changed

- `/ha`를 직렬 reasoning·execution 공통 엔진으로 정리하고, `/haq`·`/haqq`·`/haqqq`는 질문 예산만 전달하도록 단순화했습니다.
- 증거를 확인한 뒤에도 남은 사용자 소유 결정을 `must_ask`와 `decision_quality`로 나눠, 반드시 확인할 결정뿐 아니라 자료의 독자·용도·공유·권한을 바꾸는 선택도 적절히 묻습니다. 모든 tier는 후보가 없으면 질문 없이 바로 실행합니다.
- 런타임 가용성을 확인해 Codex의 Sol·Terra·Luna와 Claude의 Opus 5·Sonnet 5·Haiku 4.5 역할을 안전하게 선택하고 폴백합니다.
- Knife family의 유효한 수정 횟수에는 절대 상한을 두지 않습니다. 해결할 결함이 남은 5·15·25회에는 에이전트가 목적·계획·수정 필요성을 점검하고, 10·20·30회에는 현재 상태를 요약해 사용자 판단을 받습니다.

### Fixed

- Knife family의 문서와 프리셋이 병렬 fleet을 사용하지 않고 라운드당 최대 4문항을 지키도록 일관되게 정정했습니다.
- 질문 배치를 실제로 보낸 뒤 질문 수와 실질 라운드 상태를 갱신해, 프리셋별 상한이 다음 라운드에도 유지되도록 했습니다.
- 같은 원인의 수정·재검증을 세 번 수행하면 진행 상황과 관계없이 중단하던 규칙을 제거하고, 증거 없는 반복과 범위·보안 경계 확장을 별도로 차단하도록 수정했습니다.
