# 쓰기 범위

## `refresh/write_scope.json`

```json
{
  "since": "2026-10-10",
  "allowed": [
    "QA- 접두어를 붙인 테스트 데이터 생성·저장·수정(메뉴 규칙이 허용하면 다른 담당 회원에 QA 레코드 등록 포함). 만든 레코드 번호는 details에 기록",
    "본인 계정에만 권한 관리에서 역할 부여·회수"
  ],
  "denied": [
    "고객에게 실제 메일·문자·팩스 발송", "전화 걸기", "세그먼트 업로드 「적용하기」",
    "다른 사람이 만든 데이터 수정·삭제", "다른 사람에게 권한 부여",
    "PDF 다운로드처럼 파일을 저장하는 버튼(네이티브 저장 창)", "UI 시연 모드"
  ],
  "decisions": [
    {"date": "2026-10-10", "answer": "오늘 범위를 기본값으로", "by": "user"}
  ]
}
```

- 파일이 없으면 위 내용으로 만듭니다. 이것이 사용자가 정한 기본값입니다.
- `decisions`에는 사용자 답만 적습니다. AI가 추정한 허락은 적지 않습니다.
- WORKER.md의 「Write scope」 절은 이 파일에서 옮겨 씁니다. 「denied」에 걸리는 행은 `실행 불가`, 사유 「이번 실행의 쓰기 범위 밖」입니다(파일 저장 버튼은 「네이티브 저장 창(자동화 불가)」).

## 신규 쓰기 범위 밖 행

- `history.py`가 회차마다 쓰기 범위 밖 행 집합을 만들고, 직전 회차에 없던 TC ID를 `write_blocked_new`에 넣습니다.
- 신규가 생기는 흔한 이유는 기획 범위 확장(새 발송·연동 화면)입니다. 보고에 TC ID와 막힌 조작을 적고, 허용 여부를 한 번 묻습니다.
- 사용자가 허용하면 `allowed`에 조작을 더하고 `decisions`에 날짜와 답을 적습니다. 다음 실행에서 그 행만 큐에 넣습니다.
