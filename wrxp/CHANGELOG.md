# Changelog

이 문서는 wrxp 플러그인의 사용자에게 영향을 주는 변경 사항을 기록합니다.

## [0.1.32] - 2026-09-21

### Changed

- 검색은 직접 수행하는 것을 기본으로 하고, 여러 저장소·모듈·문서에 흩어진 대규모 지식을 넓게 탐색·압축해야 할 때만 `search-delegation`을 사용하도록 범위를 좁혔습니다. 시스템 크기나 로컬/MAGMA 여부만으로 위임하지 않습니다.
- 의뢰는 현재 맥락·질문·범위·종료 조건을 짧게 정리하며, 별도 계획 모델 호출이나 검색 비율 할당을 요구하지 않습니다. 변경을 좌우하는 조건과 충돌 근거는 주 모델이 직접 확인합니다.
- 검색 범위 지시와 실제 접근 제한을 구분하고, 공급자 연결 실패를 해결하려고 과제 밖 세션·컴퓨터 상태를 탐색하지 않도록 명시했습니다. 새로운 권한 격리 기능이나 코드 위임 실행기는 포함하지 않습니다.

## [0.1.31] - 2026-09-16

### Added

- 넓은 검색을 위임할 때 현재 작업·사용자 목적·이번 결정·제약·기존 근거와 공백을 전달하는 `search-delegation` 스킬과 의뢰 예시를 추가했습니다.
- 고유 후보의 분할, 실제 도구 접근 확인, 핵심 조건·반례를 보존하는 압축 인계, 도구 기록에 근거한 원문 참조, 필요한 부분만 재조회하는 범위를 정의했습니다. 단순 조회에는 위임을 강제하지 않으며 MCP 확장이나 자동 실행기는 포함하지 않습니다.
- Semble 로컬 검색, MAGMA 레거시 검색, 관계 조회, 알려진 파일 직접 읽기를 질문에 맞춰 선택합니다. Codex·Claude의 기존 작업자 연결을 재사용하며 같은 조사를 중복 파견하지 않습니다.

## [0.1.30] - 2026-09-15

### Added

- 기존 검사 명령의 실행·근거 수집을 담당하는 `test-runner` 스킬을 추가했습니다. 스킬이 없을 때 기존 명령을 직접 실행하는 짧은 전역 연결 규칙도 제공합니다.
- 별도 모델 없이 동작하는 Python 실행기를 포함했습니다. 셸 해석 없는 인수 전달, 명령 종료·시작 실패·시간 초과 구분, 원문 로그 스냅샷과 해시, 제한된 미리보기, 선택한 소스의 전후 해시를 제공합니다.
- 테스트 추가·자동 수정·자동 재실행·캐시를 수행하지 않습니다. 충분한 기존 실행 근거를 재사용하고, 원인 판정과 다음 결정은 주 모델이 담당합니다.

## [0.1.29] - 2026-09-13

### Added

- `staged-development` 스킬을 추가했습니다. 작업별 정본 기획서를 기준으로 사용자와 아웃라인을 합의하고, 핵심 흐름을 구현·검토한 뒤 상세 개발과 검증을 진행합니다.
- 기획서의 합의된 목적·범위·성공 조건과 실행 상태를 구분합니다. 구현 편의를 위한 요구 변경은 사용자와 합의하며, 재개와 위임 시 같은 정본을 사용합니다.
- 단순 작업의 간소화, 이미 합의된 자동 진행, 초기 불변조건 검증, 확정된 동작의 TDD, 검증 종료 기준을 포함했습니다. 기존 `ha`·`cast` 엔진의 전체 절차를 중첩 실행하지 않습니다.
- Astra의 기본 실행과 스킬 적용 시나리오를 비교한 행동 검증 기록 및 짧은 AGENTS.md 연결 예시를 추가했습니다.

## [0.1.28] - 2026-09-07

### Changed

- Codex controller와 고위험 verifier의 선호 후보를 `gpt-5.6-sol`에서 `gpt-6-astra`로 올렸습니다. GPT-6-Astra는 로컬 Codex CLI가 공개하는 모델 목록에서 우선순위가 가장 높은 최상위 모델입니다. 표준 구현·중간 리팩터링은 `gpt-5.6-terra`, 단순 탐색·국소 변경은 `gpt-5.6-luna`를 그대로 사용합니다.
- GPT-6 계열에는 Sol·Terra·Luna 같은 하위 계열이 없고 `gpt-6-astra` 하나가 최상위 모델이므로, 역할 구분은 모델 이름이 아니라 사고 수준으로 합니다.
- `gpt-6-astra`의 런타임 기본 사고 수준이 `low`라는 점을 `model-routing.md`에 명시했습니다. controller 역할에서 사고 수준을 생략하면 최상위 모델이 가장 낮은 추론으로 응답하므로, `high`를 명시적으로 전달해야 합니다.
- 기존 폴백 규칙은 그대로 적용됩니다. 런타임의 `available_models`에 `gpt-6-astra`가 없으면 같은 역할의 가용 모델 또는 런타임 기본 모델로 내려갑니다.

## [0.1.27] - 2026-09-04

### Fixed

- `/haq`·`/haqq`·`/haqqq`가 질문할 결정이 있는데도 질문 없이 실행하던 문제를 고쳤습니다. 질문 적격성 판정에 필요한 계약이 참조 문서 45KB 안에만 있어, 참조 로드가 누락되면 질문 정책이 통째로 적용되지 않았습니다. 이제 `QuestionGate` 계약을 네 진입 파일에 직접 두어 참조 문서를 읽지 못해도 판정을 건너뛸 수 없습니다.
- 공통 reasoning framework가 "사용자에게 묻는 것은 최후 수단"이라고 지시해 질문을 억제하던 문제를 고쳤습니다. 이 원칙은 증거로 확인할 수 있는 사실에만 적용되며, 승인·비공개 정책·의도처럼 사용자만 소유한 결정과 산출물의 독자·공유 범위·결정 권한을 바꾸는 선택에는 적용하지 않습니다.
- 런타임 기본 설정이 질문보다 가정을 선호하도록 안내하는 환경에서 질문 tier가 무력화되던 문제를 고쳤습니다. Codex의 Default collaboration mode가 이에 해당합니다. 질문 tier 스킬을 호출한 것 자체가 명확화를 요청하는 명시적 사용자 지시이므로, `must_ask`와 예산 안의 `decision_quality` 질문이 런타임 기본 선호보다 우선합니다.

### Changed

- 참조 문서를 필요한 시점에만 읽도록 바꿨습니다. `questioning.md`는 판정 결과가 `ask`일 때, `model-routing.md`는 첫 위임 전에, `verification.md`는 검증 기준을 정할 때 읽습니다.
- 질문 예산 산식과 카운터 갱신 규칙을 `questioning.md` 한 곳으로 모으고, 진입 파일에서 중복 기술을 제거했습니다.
- 판정 결과를 `ask`, `pass_zero`, `blocked` 세 가지로 명시했습니다. `pass_zero`는 후보를 실제로 평가한 결과가 0개일 때만 유효하며, 평가를 건너뛴 상태는 `pass_zero`가 아닙니다. 적격 후보가 없을 때 0문항으로 진행하는 기존 동작은 그대로입니다.

## [0.1.26] - 2026-09-03

### Changed

- 직접 `/ha`는 선제 discovery 질문을 하지 않고, 승인·보안·비밀·외부 변경·파괴적·불가역 경계만 즉시 확인하도록 조정했습니다. 질문 tier인 `/haq`·`/haqq`·`/haqqq`의 상한은 유지합니다.
- Knife family는 고정 직렬 실행 대신, 런타임이 공개한 동시 위임 한도 안에서 하나의 확정 의도를 dependency task graph로 실행합니다. 같은 파일·공유 상태·외부 부작용·생산자→소비자·writer→verifier 의존은 순차 wave로 유지합니다.
- `/cast`는 task 단위 병렬화와 구분되는 관점·가설 fleet에 사용하도록 역할을 명확히 했습니다.
- Codex와 Claude Code의 설치·업데이트 명령을 현재 marketplace 흐름으로 갱신했습니다.

## [0.1.25] - 2026-09-03

### Changed

- `/ha`를 직렬 reasoning·execution 공통 엔진으로 정리하고, `/haq`·`/haqq`·`/haqqq`는 질문 예산만 전달하도록 단순화했습니다.
- 증거를 확인한 뒤에도 남은 사용자 소유 결정을 `must_ask`와 `decision_quality`로 나눠, 반드시 확인할 결정뿐 아니라 자료의 독자·용도·공유·권한을 바꾸는 선택도 적절히 묻습니다. 모든 tier는 후보가 없으면 질문 없이 바로 실행합니다.
- 런타임 가용성을 확인해 Codex의 Sol·Terra·Luna와 Claude의 Opus 5·Sonnet 5·Haiku 4.5 역할을 안전하게 선택하고 폴백합니다.
- Knife family의 유효한 수정 횟수에는 절대 상한을 두지 않습니다. 해결할 결함이 남은 5·15·25회에는 에이전트가 목적·계획·수정 필요성을 점검하고, 10·20·30회에는 현재 상태를 요약해 사용자 판단을 받습니다.

### Fixed

- Knife family의 문서와 프리셋이 병렬 fleet을 사용하지 않고 라운드당 최대 4문항을 지키도록 일관되게 정정했습니다.
- 질문 배치를 실제로 보낸 뒤 질문 수와 실질 라운드 상태를 갱신해, 프리셋별 상한이 다음 라운드에도 유지되도록 했습니다.
- 같은 원인의 수정·재검증을 세 번 수행하면 진행 상황과 관계없이 중단하던 규칙을 제거하고, 증거 없는 반복과 범위·보안 경계 확장을 별도로 차단하도록 수정했습니다.
