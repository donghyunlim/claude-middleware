# /haqqq — 진짜 중요한 결정, 대충 맡길 수 없을 때

> 진짜 중요한 결정이라서, AI가 대충 해도 되는 상황이 아닌데.
> `/haqqq`는 필요한 경우에만 최대 12개(호출당 최대 4개)까지 심층 질문을 제시하고, 명시적 동의가 있을 때만 최대 20개까지 확장합니다. 하나의 확정 의도는 task graph로 실행하며, 독립 단위만 런타임이 공개한 동시 위임 한도 안에서 병렬 위임합니다.

---

## 이런 분에게 추천합니다

- **프로덕션 배포, 데이터 마이그레이션, 보안 설정** 등 되돌리기 어려운 작업을 맡기는 분
- 처음 접하는 기술 스택이나 **미지의 도메인**에서 결정을 내려야 하는 분
- 시간이 좀 걸려도 **첫 번째 시도에서 제대로** 되는 게 중요한 분
- 확정 의도를 작업 단위로 나누고 독립 verifier로 검증하길 원하는 분

---

## 어떻게 동작하나요?

### 1단계: 실행을 바꾸는 불확실성만 질문합니다

`/haq`와 마찬가지로 `/haqqq`도 물어볼 필요가 없으면 0문항으로 진행합니다. 질문은 증거를 확인한 뒤, 잘못 가정하면 안 되는 사용자 결정과 독자·용도·공유·권한처럼 산출물의 쓰임을 바꾸는 선택에 제시합니다.

작업의 모든 측면을 빠짐없이 확인합니다:

| 확인 영역 | 질문 예시 |
|---|---|
| 기술적 요구사항 | "지원해야 하는 동시 접속 수는?" |
| 비즈니스 맥락 | "이 기능의 핵심 성공 지표는?" |
| 위험 요소 | "실패 시 최악의 시나리오는?" |
| 성공 기준 | "완료의 정의를 구체적으로 말씀해주세요" |
| 제약 조건 | "변경 불가능한 기존 시스템은?" |
| 예외 케이스 | "이런 엣지 케이스는 어떻게 처리할까요?" |

이렇게 충분한 질문을 통해 불확실성을 해소하면
그 효과는 극적입니다.
난이도가 높은 문제에서 **+47%~+120% (20 Questions 과제 완료율 ~ MedDG 진단 정확도)** 의 개선이 관찰되었습니다.

> 📎 Hu et al. "Uncertainty of Thoughts" (2024) arXiv:2402.03271

### 2단계: 공통 엔진이 작업 단위를 라우팅합니다

`/haqqq`는 질문 깊이와 모델 라우팅을 분리합니다. controller는 Sol/Opus, 표준 구현은 Terra/Sonnet, 단순 탐색·국소 변경은 Luna/Haiku를 선호하며 런타임 기능에 따라 폴백합니다.

하나의 확정 의도는 **task-unit 라우팅**으로 실행합니다. 독립 unit은 런타임 한도 안에서 병렬 위임할 수 있지만, 같은 파일·공유 상태·생산자→소비자·writer→verifier 의존은 순차 wave로 처리합니다. 작성 결과는 수용 기준과 실제 증거를 확인하는 독립 verifier가 검증합니다.

관점·가설 fleet은 `/cast`의 역할입니다. `/haqqq`는 같은 답을 여러 관점에서 투표하거나 종합하는 방식이 아니라, 하나의 수렴 목표를 필요한 작업 단위와 검증 단계로 끝냅니다.

### 3단계: 검증 근거로 결과를 확인합니다

검증은 작성자의 결론을 전제로 삼지 않고 실제 파일·테스트·출처를 수용 기준에 대조합니다. 검증에서 결함이 나오면 필요한 국소 수정과 재검증으로 돌아가며, 확인할 수 없는 항목은 통과로 처리하지 않습니다.

### 4단계: 근거 없는 주장을 줄입니다

고위험 작업에서는 테스트·정적 검사·실제 파일·공식 출처처럼 관찰 가능한 근거를 우선합니다. 별도 검증 문맥을 만들 수 없으면 그 한계를 기록하고, 관점·가설 fleet이 필요한 작업으로 범위가 바뀌면 `/cast`를 선택합니다.

### 5단계: 의학 진단 수준의 정확도를 코드 작업에 적용합니다

이 심층 접근 방식의 효과는 여러 영역에서 검증되었습니다:

| 영역 | 개선 전 | 개선 후 | 변화 | 검증 지표 |
|---|---|---|---|---|
| 의학 진단 시나리오 | 44% | 97% | **+120%** | MedDG 진단 정확도 |
| 대화 기반 문제 해결 | 46% | 88% | **+92%** | FloDial 문제해결 정확도 |
| 범용 추론 | — | — | **+47%** | 20 Questions 과제 완료율 |

> 📎 Hu et al. "Uncertainty of Thoughts" (2024) arXiv:2402.03271

같은 원리가 코드 아키텍처 결정, 보안 설정,
데이터 마이그레이션 같은 고위험 작업에도 적용됩니다.

### 아키텍처 일관성: 공유 사고 체계

`/haqqq`의 심층 분석도, `/haq`의 빠른 실행도,
모두 **같은 9가지 추론 원칙**을 기반으로 동작합니다.
이 원칙들은 하나의 canonical source에 정의되어 있어,
어떤 명령어를 사용하든 일관된 사고 체계가 적용됩니다.
변경 사항은 모든 명령어에 자동으로 전파되므로,
명령어 간 품질 편차가 발생하지 않습니다.

## 사용 예시

```
/haqqq "프로덕션 데이터베이스 마이그레이션 계획 세워줘"
```

기존 스키마, 데이터 크기, 다운타임 허용 범위, 롤백 전략,
의존 서비스 목록, 검증 기준 등을 심층적으로 확인한 뒤,
필요한 task unit을 라우팅하고 독립 verifier로 검증합니다.

```
/haqqq "우리 서비스에 맞는 인증 아키텍처를 설계해줘"
```

사용자 규모, 보안 요구사항, 기존 시스템 연동, 규제 요건,
미래 확장 계획까지 파악한 뒤, 최적의 인증 아키텍처를 제안합니다.

## 이 명령어를 쓰면 안 되는 경우

- **단순하고 명확한 작업**
  — 심층 preset도 질문을 강제하지 않습니다. 빠른 작업은 `/haq`, 중간 깊이는 `/haqq`를 사용하세요.

- **시간이 급한 상황**
  — 심층 질문과 task-unit 검증에 시간이 걸립니다.
    빠른 반복이 필요하면 `/haq`가 적합합니다.

- **대규모 프로젝트 분해가 필요한 경우**
  — 여러 컴포넌트를 동시에 작업해야 한다면 `/breakdown`이 적합합니다.
