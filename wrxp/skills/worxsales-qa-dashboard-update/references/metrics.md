# 지표 정의

`history.py`가 계산하고 `render_html.py`·`sync_notion.py`가 그대로 보입니다.

## 회차

- 회차 하나는 결과 레인(`runs/run-*/`) 하나입니다. 레인의 마지막 행이 끝난 시각 순서로 번호를 매깁니다.
- 회차 k의 상태는 그 시점에 DB가 보였을 모습입니다. 그때까지 끝난 레인 가운데 `lanes.json` 우선순위(최신 먼저, `extra_lanes`는 맨 뒤)로 행마다 가장 앞선 결과를 씁니다. 그래서 마지막 회차는 `check_notion.py`와 같습니다.
- `only_ids_file`이 있는 레인(예: STG 표본)은 그 목록의 행만 셉니다.
- 빌드는 레인 결과의 `build`에서 `desktop <7자리>`를 뽑아 가장 많은 값을 씁니다.

## 분모 (대상)

- 시나리오 행은 `생성 배치` 라벨의 날짜(예: `full-2026-10-08`)부터 대상입니다.
- 현재 `정책 상태`가 「범위 제외」인 행은 모든 회차에서 뺍니다. 범위 제외가 된 날짜가 행마다 기록되지 않아서, 과거 회차의 분모는 **근사값**입니다. 진척판 하단에 이 사실을 적습니다.

## 지표 6묶음

| 묶음 | 지표 | 계산 |
|---|---|---|
| 진척 | 대상, 실행, 실행률 | 실행 = 대상 중 판정이 있는 행. 실행률 = 실행 ÷ 대상 |
| 구현도 | 구현도, OK율, 미구현율 | 분모는 실행 행. 구현도 = (OK + 부분 OK) ÷ 실행 |
| 품질 | 문제, 문제 신규, 문제 해소 | 직전 회차의 「문제」 집합과 비교 |
| 막힘 | 실행 불가 사유별 | 아래 분류 |
| 역할 | 권한 미적용 | outcome 앞 12자 안에 「권한 미적용」이 있는 행 |
| 쓰기 범위 | 쓰기 범위 밖, 신규 | 실행 불가 중 사유가 「쓰기 범위 밖」인 행. 신규 = 직전 회차에 없던 TC ID |

메뉴별 지표는 시나리오 메뉴 번호(`메뉴` 앞 숫자)마다 대상, 실행, OK+부분 OK, 미구현, 문제, 구현도를 셉니다.

## 실행 불가 사유 분류

outcome, headline, verdict_reason을 이어 붙인 글에서 키워드를 찾고, **먼저 맞은 묶음**으로 정합니다. 순서와 키워드는 `history.py`의 `BLOCK_REASONS`가 정본입니다.

1. 쓰기 범위 밖: 쓰기 범위, 실제 발송, 적용하기, 전화 걸기 등
2. 도구 한계: 주소창, 네이티브 저장 창, 픽스처, 시연 모드, 두 번째 사용자, 장애 주입 등
3. 원천 미연결: 원천 미연결, `CORE_SOURCE_UNAVAILABLE`, provider 미연결
4. 서버 설정·응답 오류: `NOT_CONFIGURED`, 응답 형식, 조회하지 못했습니다, HTTP 등
5. 데이터 없음: 사전조건, 데이터, 없습니다, 0건 등
6. 기타: 어디에도 맞지 않은 행

키워드 분류라 오분류가 있을 수 있습니다. 「기타」가 늘거나 한 묶음이 갑자기 늘면 해당 행의 outcome을 몇 개 읽고 키워드를 고칩니다.

## 진척판 구성

- 요약 띠 6칸: 위 6묶음의 현재 값과 직전 회차 대비 변화
- 회차 점도표: 회차마다 구현도(●), OK만(○), 미구현율(○). 가로축은 회차 번호, 세로축은 0~100%
- 메뉴별 점 이동: 메뉴마다 첫 측정(빈 점)과 현재(채운 점)
- 표: 회차 이력 전체, 실행 불가 사유별 회차 추이, 메뉴별 현재 값
